# Приёмка песочницы

Здесь находится активная точка входа короткой проверки песочницы.
Это организационный компонент проверок, а не физическое ядро приложения.

## С чего начать

Запускайте из корня репозитория в настроенной среде проекта:

```powershell
.venv/Scripts/python.exe -X utf8 -B -m scripts.sandbox_checks
```

Для сохранения результата укажите новый файл в существующем каталоге:

```powershell
.venv/Scripts/python.exe -X utf8 -B -m scripts.sandbox_checks --output .tools/sandbox-acceptance.json
```

Существующий output отклоняется. Нужны NumPy/SciPy, установленный Rust native
и публичные данные из репозитория. Команда проверяет оба backend и не
переключается незаметно на Python при отсутствии Rust. Подготовка среды —
в [инструкции по воспроизводимости](../../docs/reproducibility.md).

## Что где находится

| Файл | Назначение |
|---|---|
| [accept_sandbox.py](accept_sandbox.py) | Проверка научных отчётов, аналитической задачи и пользовательского цикла |
| [__main__.py](__main__.py) | Короткая команда запуска компонента |
| [../accept_sandbox.py](../accept_sandbox.py) | Совместимый вход для прежних команд и импортов; своей реализации проверок не содержит |
| [../assess_sandbox_limits.py](../assess_sandbox_limits.py) | Численный стенд изменения масс/скоростей/состава; остаётся на прежнем пути из-за закреплённых научных SHA |
| [Тесты приёмки](../../tests/test_sandbox_acceptance.py) | Целостность отчётов, отклонение подмены источника, сохранение и продолжение опыта |
| [Тесты границ](../../tests/test_sandbox_limits.py) | Шесть сценариев редактирования для Python/Rust |

Начните с run(), затем check_receipts() и workflows() в реализации.
ROOT указывает на корень проекта независимо от новой глубины папки.
Численные формулы находятся в прежнем стенде и в физическом ядре.

## Что проверяет короткая команда

1. Закреплённые source/data SHA существующих научных отчётов, строгий
   профиль и сохранность прежнего неуспешного результата.
2. Сценарий удвоения массы с независимым орбитальным эталоном, отдельно
   для Python и Rust, с прежними критериями.
3. Расчёт до точного времени, checkpoint → загрузка → продолжение,
   сохранение parent/child, добавление тела и CSV.

Результат содержит checks_passed, scientific_receipts, analytic,
workflows, wall_seconds и limitations. Ошибка проверки завершает команду
с исключением; сохранённый output сам по себе не доказывает новый годовой расчёт.

Короткая приёмка не пересчитывает год Солнечной системы и не запрашивает
новые эпохи JPL. Она не заменяет полный native-набор, проверку настоящего
portable ZIP и измерение производительности. Для других сценариев точность
автоматически не переносится.

## Совместимость и история

Прежняя команда python -m scripts.accept_sandbox и импорты ROOT,
check_receipts, workflows, run, main продолжают работать через совместимый
вход. Закреплённый assess_sandbox_limits.py и научные JSON/NPZ не менялись.
Один источник реализации приёмки; копий численных алгоритмов здесь нет.

История компонента и прежнего пути:

```powershell
git log -- scripts/sandbox_checks scripts/accept_sandbox.py
```

Описание текущего поведения находится здесь, история правок — в Git,
история выпусков — в [описаниях версий](../../docs/releases).

В375 выполнены новые годовые/holdout/sandbox расчёты. `check_receipts`
проверяет [новое доказательство](../../docs/current-runtime-375-validation.md),
его NPZ/протокол, текущие source/input SHA и измеренное environment/native.
Старые grid FAIL и Strict PASS сохранены как история. При другом окружении
или изменении вычислительных зависимостей квалификация требует новой проверки;
архивные SHA не разрешают сегодняшний solver. Это source desktop scope,
без новой portable. [Разделение исторических и текущих проверок](../../docs/development/historical-checkpoints.md).
