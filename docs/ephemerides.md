# Подготовка исходных эфемерид

Статус на 9 октября 2026: официальные данные загружены и проверены.
Сценарий solar-system подключён к GUI/CLI, работает автономно; годовая проверка
численной точности пройдена. Данные закреплены на одной эпохе, не обновляются при запуске.

## Согласованная модель

Используются Солнце (JPL ID 10) и барицентры восьми планетных систем (ID 1–8).
У барицентра Земля–Луна имя Earth-Moon: он не является центром Земли.
Спутниковые массы учитываются через GM системы, отдельно спутники не добавляются.

Начальная эпоха: 2026-10-08 00:00:00 TDB, JD 2461321.5. Координаты — относительно
барицентра Солнечной системы, геометрические векторы без световых поправок,
эклиптика J2000 на основе ICRF. Источник — DE441 в JPL Horizons.
Параметры GM берутся из официального ядра gm_Horizons.pck, по тем же ID систем.
Входные км/км·с⁻¹ переводятся в SI; GM км³/с² — в м³/с².
В существующем ядре масса задаётся как GM/G: это эквивалентная масса модели,
которая воспроизводит GM источника, а не новая независимая оценка массы планеты.

[Официальный API JPL](https://ssd-api.jpl.nasa.gov/doc/horizons.html) и
[руководство системы](https://ssd.jpl.nasa.gov/horizons/manual.html).

## Загрузка и повторение проверки

```powershell
.\.venv\Scripts\python.exe -B scripts/fetch_ephemerides.py
.\.venv\Scripts\python.exe -B scripts/assess_solar_system.py
```

Загрузчик последовательно запрашивает девять объектов, сохраняет исходные ответы
и GM-ядро в .tools/jpl-20261008, затем проверяет объект, версию API, систему координат,
единицы, эпохи и отсутствие неконечных значений. Снимок для приложения и контрольные
векторы пишутся только после полной проверки. --cached повторяет преобразование без сети.
Изменение формата/версии API требует проверки разработчиком, не молчаливой подстановки.

Снимок предназначен для пакета solar_simulator.data. Приложение затем сможет
работать без сети. В контрольной точке схемы 4 сохраняются эпоха TDB, система
координат, DE441 и SHA-256 файлов источника. Схемы 1–3 мигрируют с origin=null.
При создании нового опыта из отредактированных тел происхождение сбрасывается;
сброс исходного опыта сохраняет источник. SHA-256 идентифицирует источник данных,
но не является цифровой подписью и не доказывает подлинность вручную изменённого JSON.

## Годовая проверка

Заготовленная проверка сравнивает DOP853 с независимым RK45 в безразмерных единицах,
где силы вычисляются полной матрицей взаимодействий. Эталон дополнительно проверяется
двумя допусками. Целевой порог сравнения одной ньютоновской модели: <100 км и <0.1 м/с
для каждого тела на контрольных эпохах за один юлианский год.

Расхождение с JPL записывается отдельно. Релятивистские эффекты, отдельная Луна,
Плутон, астероиды и несферичность тел не входят в модель девяти точечных масс.
Поэтому это расхождение нельзя целиком приписывать численной ошибке интегратора.

## Запуск в приложении

В GUI выбери solar-system и нажми «Новый сценарий»; ядро python и DOP853.
Для удобного просмотра выбери «Относительно → Тело: Sun». Спутники не изображаются
отдельно: Earth-Moon — барицентр общей системы. Начальная эпоха показана над графиком.

```powershell
.\.venv\Scripts\python.exe -B -m solar_simulator new solar-system system.json
.\.venv\Scripts\python.exe -B -m solar_simulator run system.json year.json --steps 8766
.\.venv\Scripts\python.exe -B -m solar_simulator inspect year.json
```

По умолчанию dt=3600 с; 8766 таких интервалов равны одному юлианскому году.
Inspect показывает происхождение и текущую эпоху JD TDB. Радиусы в этом сценарии нулевые;
вычисляются точечные планетные системы, а не физические поверхности/столкновения.

## Измерения и ограничения

[Контрольные векторы JPL](solar-system-reference.json) и
[полные годовые результаты](solar-system-validation.json).

По 13 контрольным эпохам за год максимальное расхождение с независимым решением
той же модели — около 1.50 м (Меркурий); проверка стабильности независимого эталона
между двумя допусками даёт около 1.49 м. Поэтому это согласование решений на уровне
нескольких метров, а не доказанная абсолютная ошибка 1.50 м или гарантия на любом интервале.
Численные цели <100 км и <0.1 м/с для каждого тела пройдены.

Расхождение с JPL заметно больше: Меркурий около 154 км, Венера 96 км,
барицентр Земля–Луна 43 км, Марс 33 км. Это результат разных моделей;
нельзя утверждать, что одна только релятивистская поправка устранит все расхождения.
Необходима отдельная проверка вкладов отсутствующих тел и физических эффектов.

Позже добавлена отдельная [EIH 1PN модель и сравнение](relativity.md).
Для Меркурия/Венеры/Марса расхождения существенно сократились; для Earth-Moon
выросли до 98 км. Приведённая выше таблица относится к ньютоновской модели.

В новом [solar-system-moon](moon.md) Земля и Луна разрешены отдельно:
расхождение их барицентра с JPL в EIH 1PN уменьшилось до 165 м на контрольных
годовых эпохах. Прежний сценарий и его исторические результаты сохранены.

В Windows загрузчик использует штатный curl/Schannel с проверкой сертификатов;
на других платформах urllib со штатной проверкой TLS. Небезопасные режимы, изменение
DNS и добавление неизвестных сертификатов не используются. Меркурий/Венера могут
возвращаться в заголовках JPL как 199/299: документированные совпадающие с 1/2 барицентры,
а не разрешение произвольно заменять другие планетные ID.
