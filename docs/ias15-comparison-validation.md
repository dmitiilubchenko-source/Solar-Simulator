## Постановка и независимость

Ньютоновская взаимная гравитация двух массивных точечных тел в3D, SI,
без PN, фигур, столкновений и смягчения. Те же сохранённые начальные
декартовы компоненты и G; координаты не переносились в другой центр,
скорость центра масс сохранена. В модельных задачах время начинается с0,
астрономическая эпоха и внешние эфемериды не требуются.

Эталон — независимое эллиптическое f/g-решение Decimal100 из фактических
float64 IC с exact(G)*sum(exactmass), а не из номинальных элементов.
Проверки эталона и неопределённость Decimal70/100 сохранены из
[фазового аудита156–164](kepler-phase-validation.md). Кеш повторно принят
только после проверки source/NPZ SHA, начальных массивов и времён.

Протоколы [165](ias15-comparison-protocol.md) и
[169](ias15-original-grid-protocol.md) записаны до своих расчётов.
Пределы прежние: относительное положение<0.1м, скорость<1e-6м/с,
инерциальные E/L/P drift<1e-10. Специфическая орбитальная энергия
показана дополнительно, чтобы постоянная COM-энергия не скрывала drift.
Максимумы считаются по всем эпохам, не только в конечной точке.

IAS15 — существующая C-реализация REBOUND5.2.2. Official wheel для
CPython3.14t/Windowsamd64 и sdist сверены с SHA из PyPI. Установка локальная
в отдельном research-каталоге; основной venv и pyproject не менялись.
Исходники библиотеки/нативный бинарник проверены до и после расчётов.

IAS15 использовал basic direct gravity, epsilon1e-9 и1e-11, PRS23,
min_dt0 и начальный dt=P/10000. Epsilon не равен rtol DOP853.
Все131 или112точных границ пакетов совпадают с ContinuousRun, а не
только выходные82 или60эпох. У обоих методов запрещён overshoot;
используется сохранение контроллера и точное окончание каждого пакета.
Нет интерполяции вместо достижения проверяемой эпохи.

## Стоимость и счётчики

Таймер включает новую сессию, интегрирование и извлечение82состояний,
исключает аналитический эталон, инварианты, hashing, report, файлы и callback.
Для каждого случая выполнены прогрев и3чередующихся повтора. Все массивы
в каждом повторе побитно совпали. Суммы медиан шести случаев:

| Реализация | Сумма медиан, с |
|---|---:|
| Native Rust force + Python/SciPy DOP853 | 2.338049 |
| REBOUND C IAS15,1e-9 | 0.027433 |
| REBOUND C IAS15,1e-11 | 0.031531 |

Это сумма отдельных медиан, не медиана единого полного прогона.
Raw измерения каждого случая сохранены в JSON. Миллисекундные значения
IAS15 шумные: трёх повторов недостаточно для точной оценки малого отличия
между двумя epsilon. Сравниваются полные реализации, включая различия
арифметики сил, координат и языковой границы. Нельзя приписать весь разрыв
одному порядку интегратора, обещать такой же FPS GUI или ускорение354тел
с EIH/фигурами. У DOP853 на этой выборке к тому же есть непройденные
критерии точности; это не оптимизация при прежнем численном контракте.

Для исходного e=.95 на82эпохах DOP853 вызывает RHS7874раза; IAS15
вычисляет силу10874/14417раз. C-реализация может тратить меньше времени
при большем количестве вызовов силы. Это не доказывает эффективность
одного метода по количеству вызовов, поскольку контроллеры и арифметика
различаются. Callback счётчика выполнялся отдельно от benchmark;
массив с ним побитно совпал с обычным.

Счётчик REBOUND steps_done не является RHS. В первом receipt167 он
ошибочно назывался accepted_steps. Комментарий src/simulation.c5.2.2
указывает, что он включает failedIAS15steps; в168название исправлено,
принятые попытки по нему не сертифицируются. Весь расчёт повторён,
массивы167/168побитно равны. Первый receipt и его исходники сохранены локально.

## Следующий шаг и границы вывода

Есть измеренное основание продолжить проверку IAS15 на большем числе тел.
Следующий шаг — отдельный Newton-only профиль10тел с теми же начальными
данными и независимым сходящимся эталоном. Нельзя сравнивать голый IAS15
Newton с производственным EIH+J2 и объявлять разницу ошибкой интегратора.
Существующие строго проверенные EIH/фигуры/сохранения/GUI сохраняются.
Внедрение, дополнительные силы и перенос в Rust требуют своих измерений.

Первичные источники: [Rein & Spiegel2015](https://arxiv.org/html/1409.4779),
DOI10.1093/mnras/stu2164, и
[официальные настройки современной реализации](https://rebound.hanno-rein.de/integrators/ias15/).
Публикация рассматривает контроль округления; её результаты не выдаются
за измеренную точность Solar. Здесь получены только приведённые числа
для двух тел, выбранных IC, двух оборотов и закреплённых сеток эпох.
