# Метрология ускорения DE441: протокол294

18 октября2026, до новых вычислений. Продолжение287–293. Без новых
сил, интеграций, начальных условий, подгонки, сглаживания или удаления
неудобных эпох. Физические определения I/Q2 пока остаются открытыми.

## Источник и независимость

Тот же закреплённый архив `de441-reader-inputs.zip`: DE441 header,
115ASCII records и официальный format. Первичный format и определения
времени/осей повторно читать из архива; сеть для этого не требуется.
SI/SSB/EclipticJ2000/JD2461321.5TDB,10тел и прямой Moon−Earth.
GM внешних планет относятся к прежним системным барицентрам.

Reader использует float64 Chebyshev differentiation/Clenshaw. Новый
независимый oracle преобразует T_n в обычные степени x через
T_(n+1)=2xT_n−T_(n−1), дифференцирует степенные коэффициенты и применяет
Horner в Decimal70/90. Не вызывать chebder/chebval или старую derivative
recurrence внутри oracle. Проверить известные кубические полиномы.
Подинтервалы выбирать независимо по границам ASCII записей.

Два представления коэффициентов: точные десятичные D-токены источника
и Decimal.from_float тех же binary64, которыми пользуется reader.
Разность первого и второго измеряет только округление представления
коэффициентов, не физическую неопределённость DE441.

## Годовая сетка и заранее заданные критерии

1462эпохи через21600с,0..31557600с;1462×11 собственных норм.
Oracle70/90 для обоих представлений: относительная норма разности <1e-50.
Binary90 против reader: абсолютная норма ускорения <1e-15м/с² и
относительная <5e-13 для каждого тела и прямого относительного вектора.
Нулевой знаменатель допустим только при нулевой разности, без floor.
Все источники/массивы конечны. Raw-decimal−binary64 сохранить без критерия
«должно улучшить остаток». Это oracle того же полинома, не независимая
астрономическая эфемерида. Начать с индексов0,730,1461, затем весь год.

## Точные стыки и конечные двусторонние разности

Перечислить объединение всех границ активных позиционных блоков
внутри(0,31557600), а не считать их сеткой заранее. На каждой границе
явно выбрать левый и правый полином. Сохранить SIпределы p/v/a каждого
тела и прямой relative, jumps=right−left, вычитая в Decimal до float.
Критерии согласованности прежнего reader236: <.01м/<1e-7м/с/<1e-9м/с²
для каждого вектора, без объявления этих допусков физической точностью.

Для h=1,.1,.01,.001с разделить векторно:
D(h)=a_right(t+h)−a_left(t−h)=J+S(h),
J=a_right(t)−a_left(t),
S(h)=[a_right(t+h)−a_right(t)]+[a_left(t)−a_left(t−h)].
Вычислять фактически представленные float64 времена t±h; сохранять их
смещение от t, не вводить скрытую коррекцию времени. Тождество Decimal90
проверить абсолютной нормой <1e-50м/с². D(h) против floatreader <2e-15м/с².
Негативные контроли отсутствующего J и неверного знака J должны иметь
максимальный собственный сигнал >1e-3. Все h и все стыки сохранять;
нет требования монотонного уменьшения нормы D, возможна компенсация.

Из frozen289 брать все4модели сил, проверив source/input/NPZ/SHA и raw
qualification. Силу F(t) держать общей: d_right=F−a_right,
d_left=F−a_left. Сохранить оба, не выбирать «лучший» полином, не изменять
старые1462метрики. Проверить d_right−d_left=−J с абсолютным порогом
2e-15м/с². Выбор ветви меняет только reference acceleration, не пересчитывает
силу по немного отличающимся левым p/v. Причинная атрибуция реальной
орбитальной ошибки и истинное ускорение этим не устанавливаются.
