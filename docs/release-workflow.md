# Ветки, версии и готовность выпуска

Разработка ведётся в `dev`. В `main` переносятся законченные выпуски после
приёмки; сохранённые теги `vX.Y.Z` обозначают конкретные выпуски и не передвигаются.
Коммиты и push в `dev` сохраняют работу, но сами по себе не являются выпуском.

## Исходное состояние после разделения веток

- Первый опубликованный выпуск — `v0.2.0`, commit
  `25872046e739b13c215c90601fb6bee7f127e663` от 6 октября 2026.
- При создании `dev` ветка `main` уже содержит более новый проверенный checkpoint
  `7c7217cdf502f68b917bd398890008ff3ddb324d`. Он сохранён без отката истории.
  Это не точная копия `v0.2.0` и не новый принятый выпуск с portable.
- Последующие изменения идут в `dev`; следующий планируемый выпуск — **0.3.0**.
  Это целевой номер, а не объявление готовности. Кандидат в dev — 0.3.0rc1.
- Последняя проверенная локальная portable и публичный выпуск `v0.2.0` — разные
  артефакты. Точные сведения о локальной поставке: [карта проекта](project-map.md).

Таким образом, переходная `main` заморожена на сохранённом checkpoint.
Для первого публичного выпуска следует выбирать тег `v0.2.0`, а не вершину `main`.
Со следующего принятого выпуска вершина `main` и его тег будут совпадать.

## Когда менять номер

- Исправления без заметного расширения возможностей: следующий patch, например
  0.2.1 для отдельного исправления ветки 0.2.0.
- Законченный набор новых возможностей: следующий minor, в данном случае 0.3.0.
  Количество итераций, тестов и прошедших дней не определяет номер.
- Несовместимые изменения требуют описания миграции и отдельной оценки номера;
  версия 0.x ещё не обещает неизменность всех интерфейсов.

Номер обновляется в `dev` при подготовке конкретного кандидата до его окончательной
проверки и сборки. Меняются актуальные метаданные Python, версии Rust-компонентов
и соответствующие Cargo.lock, если выпуск обновляет их совместно. Проверяются
имя wheel/portable и версии фактически установленных компонентов. Старые отчёты,
рецепты, SHA и архивы с номером 0.2.0 сохраняются; массовая замена запрещена.
Изменение номера требует пересборки соответствующих компонентов и проверок
финального кандидата: результаты старой сборки не переносятся на него автоматически.
Тег и GitHub Release не создаются при одном лишь изменении номера.

## Условия переноса в main

1. Состав выпуска и критерии готовности определены; обещанные сценарии закончены.
2. Проверен именно финальный кандидат: полная приёмка
   `scripts/check_project.py --require-native`, реальный native, Rust fmt/tests и отсутствие пропусков в
   проверенной desktop-среде. Код, данные и binary не меняются во время проверки.
3. Если менялась физика, интегратор или научные входы, выполнены относящиеся
   независимые проверки с сохранением отказов, стоимости и границ применимости.
   Количество тестов и повторяемость кадров сами по себе не измеряют точность.
4. Для desktop-выпуска собраны ZIP/SHA и пройдена приёмка настоящего ZIP после
   свежей распаковки с изолированным runtime/LOCALAPPDATA. Новые возможности
   проверены в поставке; установленная версия совпадает с метаданными кандидата.
5. Актуальны руководство и описание выпуска; личные файлы, recovery и сборочные
   кеши исключены из Git. Обязательные публичные научные входы сохранены.
6. Нет нерешённого отказа, нарушающего критерии выпуска. Исследовательские режимы
   с известными ограничениями явно отделены от принятых сценариев и точности.

После приёмки — проверка актуальности удалённой `main`, обычный merge из `dev`
без переписывания истории, тег `vX.Y.Z` на принятом коммите и отправка в явно
разрешённом пользователем объёме. Предпочтителен fast-forward; при расхождении
веток сначала согласовать и проверить объединённый результат. Обе ветки должны
содержать принятый коммит; затем работа продолжается в `dev`. Force-push и
перемещение старых тегов не входят в обычный выпуск. GitHub Release и загрузка
артефактов — отдельные действия публикации, не следствие смены номера.

## Что сообщается в конце рабочего этапа

Краткий результат и проверки, затем:

- Коммит: нужен / пока рано / выполнен, с причиной.
- Push: в какую ветку нужен / пока рано / выполнен, с причиной.
- Следующая версия: целевой номер и статус «не готова», «кандидат» или
  «приёмка пройдена», с перечислением оставшихся препятствий и рекомендацией
  о переносе в `main`. Исходники, portable и физическая квалификация оцениваются
  отдельно; неизмеренная точность не обещается.

Отчёт — рекомендация, а не автоматическое разрешение публикации. Он не требует
останавливать уже разрешённую разработку после каждого этапа.
