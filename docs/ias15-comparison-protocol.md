# Независимое сравнение IAS15

15 октября2026, изменение165. До интегрирования проверочных траекторий.
Цель — проверить другую существующую реализацию на случаях, где DOP853
не выполняет общий критерий. Это исследование, не замена ядра приложения.

## Модель и исходные данные

Те же шесть ньютоновских двухтельных сценариев160, все82эпохи и два
номинальных периода. SI, наклонные декартовы оси, начальный центр масс и
его скорость сохранены; физическая эпоха/эфемериды для модельной задачи
не требуются. Начальные массы, положения и скорости добавляются напрямую
из записанных компонентов, без orbital-element constructor и move_to_com.
G совпадает с Solar, мягчение0, все тела массивные, столкновений/PN/Q2 нет.
Никаких подгонок по будущей траектории.

Oracle — exact-initial Decimal100 из неизменного кеша160/163, с проверкой
его source/NPZ SHA и начальных массивов/эпох. Decimal70/100 uncertainty
и независимые аналитические проверки сохранены из
[предыдущего аудита](kepler-phase-validation.md).

Источник/библиотеку проверять до и после; установка только в локальный
research-каталог, без изменения pyproject/зависимостей приложения.

IAS15: basic direct gravity, epsilon1e-9 и1e-11 как два заранее выбранных
уровня, adaptive_mode=PRS23, min_dt=0. Начальный dt=P/10000; затем выбирается
адаптивно. Epsilon IAS15 не равен rtol DOP853, численные значения не сравнивать.
Настройки проверять чтением обратно. В5.2.2 API — sim.integrator.epsilon,
не прежний sim.ri_ias15; state содержит внутренний указатель, не объект.

Первичные источники:
[Rein & Spiegel2015, IAS15](https://arxiv.org/html/1409.4779),

[текущие параметры](https://rebound.hanno-rein.de/integrators/ias15/),

сравнение современного пакета за дословное воспроизведение её эксперимента.

## Критерии и стоимость

1. Точные начальные компоненты, количество/порядок тел, массы/G/безsoftening.
   По всему времени — exact_finish_time=1, все те же промежуточные границы
   packet1, которые использует ContinuousRun, а не только82выходных эпохи.
   Ни overshoot, ни dense interpolation. Контроллер сохраняется между вызовами.
2. Максимальные относительные ошибки по82эпохам: положение<0.1м,
   скорость<1e-6м/с, прежние независимые E/L/P drift<1e-10. Дополнительно
   показать специфическую орбитальную энергию, чтобы постоянная энергия
   центра масс не скрывала относительный orbital drift. Все отказы сохранять.
3. Повтор IAS15 побитно равен первому; DOP853 на тех же исходных данных
   побитно повторяет прежние массивы160/163. Контроль с двумя epsilon —
   чувствительность, не гарантия монотонности или физической точности.
4. Одно прогревание каждого метода/сценария, затем3чередующихся повтора
   DOP853/IAS15-1e-9/IAS15-1e-11 и в обратном порядке. Одинаковые131точные
   границы пакетов и82выходных состояния. Таймер включает создание сессии,
   интегрирование и извлечение массивов; аналитика, report, файлы и hashing
   исключены. Никакого gate скорости или автоматической замены по времени.
5. Счётчик steps_done IAS15 отдельно от RHS DOP853: разные счётчики. Число силовых
   вызовов IAS15 считать в отдельном нетаймируемом прогоне no-op callback;
   его массив должен побитно совпасть с вариантом без callback. Python callback
   не должен попадать в benchmark. Время сравнивает полные реализации с
   разными force arithmetic/языками, не изолированную стоимость формулы метода.

Уточнение168: в src/simulation.c5.2.2 комментарий к steps_done указывает,
что счётчик включает failedIAS15steps. Поэтому ранее использованное в
первом receipt название accepted_steps исправлено на буквальное steps_done;
не утверждается число принятых внутренних попыток. Численные операции,
исходные данные, критерии и способ подсчёта force evaluations не меняются.

Даже успех6/6 не аттестует Solar10год,354тела, EIH/фигуры, пользовательские
редактирования или непрерывную точность между эпохами. Никаких новых
интерфейсов интеграторов, runtime/schema/GUI/portable изменений в этом этапе.
