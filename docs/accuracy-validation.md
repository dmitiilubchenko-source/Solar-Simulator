# Контроль точности DOP853

Измерения: 8 октября 2026 года. Ошибка сравнивается с аналитическим решением двух тел, а не с другим запуском того же интегратора.

## Измеренная ошибка

Один период Солнце–Земля, 100 контрольных снимков. Для Verlet — 8000 физических шагов; для DOP853 те же интервалы выдачи состояния и адаптивные внутренние шаги. Координаты измеряются в относительном движении тел. Это численная ошибка выбранной ньютоновской модели.

| Эксцентриситет | Verlet: ошибка координат, м | DOP853 (rtol=1e-13): ошибка координат, м | DOP853: ошибка скорости, м/с |
|---|---:|---:|---:|
| 0 | 201936 | 0.00220065 | 4.05891e-10 |
| 0.3 | 763338 | 0.0576029 | 1.55651e-08 |
| 0.6 | 1.26037e+07 | 0.764345 | 4.71661e-07 |
| 0.9 | 8.7123e+09 | 8.85883 | 4.04579e-05 |

Порог проверки DOP853: <100 м координат, <0.001 м/с скорости, <1e-10 относительной ошибки энергии. Все четыре орбиты проходят как с rtol=1e-13, так и с rtol=3e-14. Более строгий допуск не всегда даёт меньшую ошибку: например, на круговой орбите оба результата уже близки к пределам арифметики и накопления округлений. Максимумы относятся к снимкам и не являются верхней границей на всех промежуточных моментах.

## Реализация и проверки

- DOP853 SciPy с раздельными абсолютными допусками координат/скоростей, работа в системе движущегося центра масс.
- Формула ускорений ньютоновская, попарный расчёт O(N²). Новые силы не добавлялись: причина прежней ошибки была численной.
- Эталон: аналитическое уравнение Кеплера, решённое бисекцией; эталон не использует solve_ivp или рабочую формулу ускорения.
- Дополнительные проверки: точное трёхтельное решение равностороннего треугольника, вращение/перенос/общая скорость, десять орбит, свободное движение, сохранение/продолжение, миграция JSON и работа GUI.

```powershell
.\.venv\Scripts\python.exe -B scripts/assess_accuracy.py --output .tools/accuracy-check.json
.\.venv\Scripts\python.exe -B scripts/check_project.py
```

[Полные измерения](accuracy-validation.json) содержат настройки, версии среды и SHA-256 скрипта/ядра. Порог нарушен — проверочная команда возвращает ошибку.

## Границы

DOP853 доступен в интерфейсе и CLI через Python/SciPy. Новый обычный запуск GUI использует его; загрузка старых JSON сохраняет Verlet. У точечных сценариев Python в CLI new по умолчанию DOP853, у Rust и контактных сценариев — Verlet. Метод и допуски сохраняются в схеме 3. SciPy включается в новые переносимые сборки; ранее опубликованный ZIP 0.2.0 не обновлялся.

Локальная оценка ошибки не гарантирует глобальный допуск. В converge для DOP853 сравниваются более строгие допуски; метод Ричардсона второго порядка не применяется. По мере уменьшения rtol ниже 3e-14 реализация явно отказывает, поскольку дальнейшая точность float64 не поддерживается.

Нет обещания нулевой ошибки, точности реальных эфемерид или любых будущих N-тельных сценариев. Неопределённость масс/начальных условий и отсутствующие физические эффекты отдельно влияют на соответствие природе. DOP853 не является симплектическим методом; очень длинные интервалы нуждаются в отдельной проверке фазового и энергетического дрейфа. Столкновения и ненулевые радиусы явно запрещены в этом режиме; для них используется прежняя проверенная контактная модель Verlet.
