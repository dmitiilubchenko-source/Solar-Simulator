# Solar Simulator 0.2 — руководство

Это настольная лаборатория ньютоновской гравитации. Она рассчитывает
взаимное движение тел в 3D и показывает выбранную двумерную проекцию.
Начальные астрономические сценарии учебные; они не описывают положения
планет на сегодняшнюю дату. Во всех файлах и полях используются SI.

## Быстрый запуск

В исходном проекте открой `Запустить.cmd` либо выполни:

```powershell
.\.venv\Scripts\python.exe -B -m solar_simulator gui
```

В переносимой сборке распакуй ZIP и открой `Solar Simulator.cmd`.
Её каталог `runtime` содержит собственный Python, библиотеки и Rust-модуль.
Для этой сборки не нужны установка Python, Rust или настройка PATH.
Не переносить один CMD без остальной папки. Сборка предназначена для
Windows x64 и проверена на текущем компьютере; другой компьютер отдельно
не проверялся. Это переносимая папка, не подписанный установщик.

## Интерфейс

1. Выбери сценарий и нажми «Новый сценарий». Для Солнце–Земля можно
   задать эксцентриситет: 0 — круг, значение меньше 1 — эллипс.
2. Выбери ядро Python или Rust и физический шаг `dt` в секундах.
   «Применить параметры» применяет их к текущему состоянию. Изменение
   ядра/шага в середине опыта меняет численный эксперимент.
3. «Запуск», «Пауза», «Один шаг» управляют расчётом. Пауза завершает
   уже отправленный пакет; она не прерывает отдельный физический шаг.
4. «Шагов за кадр» задаёт скорость воспроизведения (1–2000), сохраняя dt.
   Увеличение этого числа не снижает число физических шагов на орбиту,
   но делает снимки и графики более редкими.
5. Выбирай XY/XZ/YZ и систему относительно нужного тела. Физика считается
   в инерциальной системе; выбор относительного вида меняет только график.
6. «Изменить тело…» позволяет менять имя, массу, радиус, положение и
   скорость. Применение создаёт новый опыт из текущих положений остальных
   тел и сбрасывает время, траектории и исходную энергию. Унаследованный
   spin сохраняется; его ручной ввод доступен через JSON.
7. «Сохранить JSON» сохраняет текущее состояние и исходный сценарий;
   «Открыть JSON» восстанавливает контрольную точку, «Сбросить» возвращает
   её исходные тела с текущими параметрами расчёта.

Расчёт идёт в рабочем потоке; изменяющие состояние кнопки временно
заблокированы. Закрытие окна не обрывает уже выполняющийся пакет силой.
С Rust весь цикл точечных тел/отскоков выполняется нативно. Детектор Rust
отличается от NumPy-реализации, поэтому совпадение результатов проверяется
с допусками, а не обещается побитовое равенство между ядрами.

Маркеры увеличены для видимости и не показывают физический радиус.
Траектории/диагностики хранят последние 1500 кадров; файл состояния хранит
физические тела и события, а не отрисованный след. При загрузке след
начинается заново. Масштаб обновляется автоматически при отрисовке;
панель Matplotlib удобна для исследования графика на паузе.

## Контакты

| Режим | Поведение |
|---|---|
| `stop` | Остановка при первом касании, включая касательную траекторию |
| `bounce` | Последовательные импульсные удары гладких сфер без трения |
| `merge` | Замена касающейся пары одним телом с сохранением массы и импульса |

Контакты есть только при положительной сумме радиусов пары. У стандартных
астрономических сценариев радиусы нулевые. Сценарий `spheres` использует
два искусственных тела радиуса 1 м и по умолчанию показывает отскоки.

Упругость `e=1` означает упругий удар; при `0<e<1` часть нормальной
кинетической энергии исчезает из разрешённого движения и записывается
как потери. `e=0` сам по себе не сливает тела и может привести к
покоящемуся контакту, для которого нужен решатель контактных сил.

Слияние задаётся отдельной моделью: радиус определяется сохранением суммы
объёмов, положение/скорость — центром масс. Угловой момент относительного
движения переходит в `spin` нового тела (кг·м²/с). Spin пассивен: нет
вращательного движения, ориентации, трения и крутящих моментов. Энергия
в отчёте — кинетическая энергия центров и попарная потенциальная энергия;
вращательная энергия, тепло и собственная гравитационная энергия тел
в неё не входят. Подписанный скачок `model_energy_offset` фиксирует
замену двух тел одним, включая изменение взаимодействий с третьими телами.
Это учёт смены модели, а не решение термодинамики планетного столкновения.

Одновременные контакты нескольких пар, глубокие перекрытия и устойчивый
контакт для bounce вызывают ошибку. Ограничение количества отскоков
защищает от неупругого коллапса. После ошибки исходная контрольная точка
не заменяется частично рассчитанным состоянием. При остановке `stop`
можно явно выбрать bounce/merge и применить параметры либо сбросить опыт.

## Диагностика и точность

Смотри одновременно на траекторию, полный импульс, угловой момент,
центр масс и остаток энергетического баланса:

`E_current + dissipated_energy + model_energy_offset − E_initial`.

Второй порядок Verlet проверен сравнением шагов. Маленькая ошибка энергии
не гарантирует маленькую фазовую ошибку. Крупный dt особенно опасен для
эллипсов с высоким эксцентриситетом и тесных сближений. Контакт вычисляется
по параболе численного шага, поэтому тоже требует проверки сходимости.

```powershell
.\.venv\Scripts\python.exe -B -m solar_simulator new sun-earth initial.json --backend rust
.\.venv\Scripts\python.exe -B -m solar_simulator converge initial.json --steps 4000
```

Сравниваются dt, dt/2, dt/4 на одном интервале. Для гладкого движения
отношение соседних разностей обычно стремится к 4 в режиме второго
порядка. Оценка ошибки по Ричардсону предполагает этот режим; это не
гарантированная верхняя граница. При контактах такая оценка отключена;
при остановке или разном составе тел сравнение координат прекращается
с пояснением. Проверь также времена событий при уменьшении шага.

## CLI и контрольные точки

```powershell
# Создание, продолжение, диагностика:
.\.venv\Scripts\python.exe -B -m solar_simulator new spheres initial.json --backend rust --contact-mode merge
.\.venv\Scripts\python.exe -B -m solar_simulator run initial.json final.json --steps 2000
.\.venv\Scripts\python.exe -B -m solar_simulator inspect final.json
# Открыть сохранённое состояние:
.\.venv\Scripts\python.exe -B -m solar_simulator gui final.json
```

В переносимой папке используй `runtime\python.exe` вместо пути `.venv`.
CLI `run` сначала рассчитывает результат и только потом заменяет выходной
файл. Запись атомарна через временный файл в том же каталоге. Родительский
каталог должен существовать. Загрузка отвергает NaN/Infinity, повторные
поля JSON, неподдерживаемые единицы/версию, неверные векторы и историю.

Формат версии 2 содержит настройки, исходные и текущие тела, время,
потери, скачки энергии, spin и события слияний. Версия 1 автоматически
читается с нулевыми spin/скачками. Продолжение через сохранение проверено
на обоих ядрах. Совпадение с непрерывным запуском требует тех же dt,
модели и границы физического шага; контактная остановка хранит своё время.

## Разработка и сборка

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,native]"
.\.venv\Scripts\python.exe -B scripts/build_native.py
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -B scripts/check_app.py
.\.venv\Scripts\python.exe -B scripts/build_portable.py
```

Для разработки Rust нужен Cargo. Windows-сборка использует Python/Tk
из текущего окружения и копии установленных зависимостей с их лицензиями.
Скрипт строит Python wheel и native wheel, проверяет изолированные импорты,
Tk и запуск приложения, создаёт новую папку/ZIP и SHA256 в `dist`.
На этой машине интерпретатор свободнопоточный CPython 3.14t; native wheel
привязан к его ABI. В переносимом архиве соответствующий Python уже есть.

Физические формулы: `physics.md`; архитектура Rust: `rust.md`.

## Границы и следующие большие задачи

Нет эфемерид, ОТО, приливов, атмосферы, гидродинамики, фрагментации,
вращательной динамики и решения устойчивых/одновременных контактов.
Нет адаптивного физического шага и универсального автоматического
контроля ошибок. Попарная гравитация O(N²) предназначена для небольших
экспериментов; загрузчик ограничивает файл 10 МБ и 1000 тел.

Для следующих этапов нужны отдельные проверяемые физические модели:
контактные ограничения, динамика вращения, импорт согласованных эфемерид,
адаптивный интегратор для сближений. SQLite имеет смысл для каталога многих
опытов; сервер и PostgreSQL пока не нужны. Переход на PySide6 можно делать
для более сложного интерфейса; текущая лаборатория использует доступный
Tk без новой тяжёлой зависимости.
