# Внутренняя арифметика Rust DOP853: протокол337

20 октября 2026, до новых расчётов. Продолжение диагностики335–336.
Цель — измерить локальные потери стадий и обновлений при прежней траектории,
не исправлять интегратор и не объявлять причину глобальной ошибки заранее.

Исходники337 до правок побитно сверены с exact dirtyZIP335 и сохранены
локально. Исходные отчёты335/336, их SHA, NPZ и executable сохраняются.
Исторические SHA не заменяются текущими; изменённый код получает новый receipt.

Добавляется только отключённая по умолчанию feature `diagnostic-trace`
отдельного research-crate `rust/solar_adaptive`. Recorder принадлежит сеансу,
пишет новый JSONL и явно сообщает отказ записи. Нет глобального recorder,
production FFI, новых сил, зависимостей или формата checkpoint приложения.
Записываются исходное состояние, h, K, суммы/результаты11 стадий,
финальная B-сумма/предложение, локальная ошибка и accepted/rejected.
Проверка header/конца записи должна обнаруживать неполный поток.

## Обязательный контроль до интерпретации

Все9 прежних входных JSON335, массы/IC/rtol/atol,6×82/3×60 эпох и пакеты.
Модель Newton2point/SI/3D/t0=0/2периода/relativeA-B. Запустить release
без feature, с feature без записи и с записью. Все состояния (включая t0),
эпохи, границы и счётчики побитно равны335. Если нет — остановить интерпретацию,
сохранить отказ, не подбирать step/фазу/допуски. Все5PASS/4FAIL335 прежние;
0.1м/1e-6мс/E-L-P1e-10 не менять, к10тел/году не переходить.

Для каждой попытки проверять K/размерности/конечность, последовательность
старого/нового состояния и h, error<1 ↔ accepted, итоговые счётчики и конец
потока. Восстановить наблюдённые суммы/операции binary64 в том же порядке;
результаты обязаны совпасть битами. Затем для тех же операндов использовать
`Fraction.from_float`, точные двоичные рациональные произведения и суммы.

При S=наблюдённая float-сумма, Q=точная сумма a_j K_j:
δdot=h(S−Q), δmul=float(h S)−h S,
δadd=observed_new−(old+float(h S)). Их точная сумма должна равняться
observed_new−(old+h Q) для каждого компонента каждой стадии/предложения.
Все входы Fraction — exact(binary64); это не интегрирование в повышенной
точности. Ошибка коэффициентов относительно математических констант,
ошибка RHS, усечение метода и управление шагом сюда не входят.

Отдельно показать максимумы компонент относительных r(3:6) в метрах и
v(9:12) в м/с, стадии/принятые/отклонённые предложения. Для принятых
обновлений дополнительно signed/absolute суммы δadd по трём осям.
Эти суммы без матрицы распространения возмущений НЕ оценивают глобальную
орбитальную ошибку. Отказы стадий не переносят состояние; recorder не
вычисляет поправку и не изменяет следующий шаг.

Точные искусственные случаи должны различать потерю суммы произведений,
умножения и прибавления к большому состоянию; проверить отрицательные
приращения, нули и обнаружение повреждённого trace. Rust-проверки:
включение/отключение записи, независимость сеансов, запрет перезаписи,
явный отказ записи с сохранением последнего committed snapshot.

Сохранить новый source/binary/input/trace SHA, версии и параметры сборки,
commit/dirty-снимок, число/размер записей и стоимость самого анализа.
Полные сырые trace локальны; публичный отчёт содержит все9 summaries и
команды воспроизведения. На время измерений код/данные не менять.
Никакого benchmark/обещания ускорения, новой portable или замены runtime.
