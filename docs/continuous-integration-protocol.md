# Протокол продолжения DOP853

15 октября2026, до реализации и просмотра результатов. Цель — уменьшить
стоимость повторной инициализации при прежних границах кадров и допусках.
Проверенный `advance`/`evolve_accurate`, настройки, JSONschema и строгая
демонстрация остаются прежними. Новый режим явный и отдельно проверяется.

## Численный метод и область

Тот же DOP853 и текущая per-body норма, те же nativeNewton/EIH1PN силы,
фигуры, relativeEarthMoon и SI. Инициализировать один solver на начальном
снимке; сохранять `y/f/h_abs` между пакетами. Перед пакетом продлевать
`t_bound`, переводить только успешно finished solver обратно в running.
Не сбрасывать failed; останавливать каждый пакет точно на заданной эпохе,
без расчёта будущего кадра и без dense interpolation. Постоянные центр и
drift исходного снимка сохраняются; EIH получает инерциальные скорости.
Это иной численный путь, не обещается bitexact совпадение с рестартами.

[Первичный SciPy DOP853](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.DOP853.html),
[исходный алгоритм Hairer](https://www.unige.ch/~hairer/software.html).
Используется установленный SciPy1.18.1; управление status/t_bound зависит
от его реализации. Версию/installedsourceSHA фиксировать, неподдерживаемую
версию отклонять, не делать скрытый fallback. Силовые формулы не меняются.
Начально только Rust point Newton/EIH, fixed/prescribed Q2, per-body.
Контакты и динамическое вращение отвергать; Python-only/старые режимы сохранять.

## Критерии до расчётов

1. Независимые наклонные аналитические Kepler пары, e0/.5/.95, rtol3e-14:
   2периода,50равномерных+перицентр-окрестности; relativeposition<0.1м,
   velocity<1e-6м/с, independentE/L/P drift<1e-10. Восстанавливать полную
   трёхмерную орбиту, не проверять только конечную точку/энергию.
   Инерциальное свободное тело: exacttarget и float64roundoff.
2. Жизненный цикл: packets20/изменениеpacket/точныйдробныйtarget, noovershoot,
   input/outputs независимы, повторения bitexact, errorнепродолжается,
   save/load/новаяsession послепаузы иreset/settings/bodychange.
   После reload не обещать тотже solverbuffer; drift<0.1м/body,0.01м/pair
   на8⅓суток354профиля и <1e-6м/с; старыеформаты не меняются.
3. Strict10body/год,125прежнихэпох/packet20. Сначала свободный расчёт,
   затем ранееSHA-verified independentRK45 reference139/141: per-body
   <10м/1e-4м/с, Earth–Moon<0.1м/1e-5м/с. Неопределённость reference
   all0.098723м/pair0.003040м сохраняется. DenseJPL144/145 goals10км/body
   и1км/pair; ни подгонки, ни измененияданных/сил. Старый139FAILED сохранять.
4. Native354catalog EIH+prescribedQ2/rtol3e-14/x1e-7м/v1e-13м/с:
   720000с,10одинаковыхpacket20эпох, per-body differences к прежним
   restart <0.1м/1e-6м/с, pair<0.01м/1e-6м/с. Это agreement, не oracle.
   Independent Newton/EIH/figureforce тесты дополняют, не заменяют
   проверку нового интегратора. Не объявлять whole354year trueaccuracy.
5. Двауровня independentRK45 для полного354короткогоинтервалаеслистоимость
   позволяет; сначала pilotстоимость, отдельныйвременнойпротокол/критерии
   доосновногопрогона. При неподъёмнойстоимости сохранять ограничение,
   не изображатьпройденным. Критерии3/4 уже определены.
6. Стоимость354 на техже10epoch720000с: warmup+3alternatingповтора,
   времяphysics иphysics+report, RHScounts отдельно. Gate≥15% уменьшения
   медианы полногоphysics+report; та же сетка, количество кадров/допуски,
   без сериализации/профилировщика внутритаймера. Ошибкидолжны пройти
   независимо отspeed. Числа150не использовать кактекущийpairedbaseline.

Все SHA/runtime/данные/cache до запуска и после результатов проверять.
Если критерий не прошёл — сохранить неуспех; не менять порог после результата.
Годовая354qualification, GUImode/storageмиграция и полныйRustport не
обязательны для первого проверенного явного headless режима. В UI режим
можно внедрять только с записанным способом воспроизведения/продолжения;
никаких скрытых переключений в уже проверенных опытах.
