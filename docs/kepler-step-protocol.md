# Проверка ограничения внутреннего шага

15 октября 2026, изменение157, до результатов.
Исходные данные и аналитика из [протокола156](kepler-phase-protocol.md).
Только e=.95, два периода, все60эпох; exactDecimal100 reference156.
Исходный JSON SHA256: dc8bf5a3e1f346b5bb43ee693e940d9a1eac32d71b4f3ef898fe6c7c533dccaa.

Сохраняются rtol3e-14, xatol1e-7м, vatol1e-13м/с, nativeNewton,
per-body, relativeA/B, packet1. Пять caps: period/500,/1000,/2000,/4000,/8000;
uncapped повтор должен побитно повторить исходный массив156.
Независимая переменная — max_step SciPy, не шаг снимков/истории/GUI.
Только подстановка конструктора в проверочном процессе; runtime неизменен.
Положение <0.1м, скорость <1e-6м/с, E/L/P drift <1e-10, те же критерии.
Результаты каждогоcap, cost и RHS сохраняются, включая неуспехи.
Одно измерение времени показывает порядок стоимости, не pairedbenchmark.
Пять уровней показывают чувствительность, не гарантируют монотонную
сходимость в области округления. Ни одногоcap не внедрять автоматически
по одному удачному исходу; универсальность ещё требует проверки.

Уточнение163 до повторного запуска: исходный SHA выше остаётся историческим.
Новый расчёт имеет иное время выполнения и другой SHA JSON. Для него
проверяются sourceSHA, отдельный NPZ SHA из receipt и прежние точные
начальные данные/эпохи. Следующий результат связывается с полным SHA
фактически использованного JSON. Отсутствие NPZ-привязки требует нового
расчёта, повреждённые массивы или изменённые источники отклоняются.
