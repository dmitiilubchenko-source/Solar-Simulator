# Проверка: вектор Луна−Земля из DE441

20 октября 2026, демонстрационный пример предложения v0.3, изменение 333.

**Статус:** `PASS` для чтения и преобразования данных в границах
[действующего протокола](de441-reader-protocol.md).
**Граница задачи:** происхождение относительного вектора, единицы, оси
и связь с проверками читателя. Движение тел здесь не интегрируется.

## Источник и формула

Первичный документ JPL — [INTERNAL FORMAT OF THE EPHEMERIS FILES](https://ssd.jpl.nasa.gov/ftp/eph/planets/ascii/ascii_format.txt).
Проверены список позиционных компонент (десятая — `Moon (geocentric)`),
описание `GROUP 1050` и заключительный абзац об единицах километров,
совместимых с TDB. Это геоцентрический вектор Луны; колонка EMB отдельно
содержит барицентр Земля–Луна. Их нельзя подменять друг другом.

В [руководстве Horizons](https://ssd.jpl.nasa.gov/horizons/manual.html#ecliptic)
проверены разделы **General Definitions → Reference Frame → Ecliptic**:
фиксированный наклон для J2000 равен 84381.448 угловой секунды.
Используемая ниже матрица соответствует преобразованию осей читателя.
Источникам не приписываются отсутствующие номера уравнений.

Обозначим геоцентрический вектор из DE441 через `q(t)` в километрах/ICRF.
Тогда искомый вектор в метрах/Ecliptic J2000:

```text
rho(t) = r_Moon(t) − r_Earth(t) = 1000 R q(t)
R = [[1, 0, 0], [0, cos(epsilon), sin(epsilon)],
     [0, −sin(epsilon), cos(epsilon)]]
epsilon = 84381.448 pi / (180 × 3600)
```

Это вывод из геоцентрического определения, линейности преобразования осей
и перевода km→m. Время — секунды TDB от JD2461321.5; UTC сюда не подставляется.
Для скорости и ускорения применяется та же постоянная матрица к производным
полинома по секундам. Для нормированной координаты полинома
`x = 2(t − t_start)/span_seconds − 1` каждая производная добавляет множитель
`2/span_seconds`. Уравнения и ограничения чтения уже закреплены в протоколе.

Прямое чтение `q` позволяет не вычитать два больших барицентрических
float64-вектора. Это не обещание нулевой ошибки округления.

Полные первичные тексты и заголовок DE441 прочитаны из
[сохранённого архива](de441-reader-inputs.zip); SHA архива и каждого файла
проверяет `load_archive`. Их URL, SHA и происхождение закреплены в
`provenance.json` внутри архива. Новых загрузок не выполнялось.

  проверяет относительный вектор, преобразование осей и единиц.

  [JSON](de441-reader-validation.json) содержат критерии, измерения,

Decimal и синтетическая аналитика дают независимость вычислительного способа.
Horizons и локальные коэффициенты здесь относятся к тому же DE441:
их совпадение проверяет чтение и соглашения, а не даёт второй независимый
астрономический эталон. Сверка тестов не доказывает всю физическую модель Solar.

## Что проверено сейчас и как повторить

Повтор выполнен на коммите `a82fc8b1f487d361287e60b943d2f0c738e352a2`,
с чистым рабочим деревом до измерений. Карточка добавлена после прогона.
CPython 3.14.2, NumPy 2.5.1, SciPy 1.18.1; проверен настоящий native-модуль.
Шесть исходных привязок SHA опубликованного аудита совпали с текущими файлами.

Выполнены 30 связанных тестов без пропусков и существующая функция
`scripts.assess_de441_reader.run` с выходом
`.tools/card333/verified/reader-audit.json`: `complete=True`, `checks_passed=True`.
На время аудита `socket.socket.connect` и `socket.create_connection`
были заблокированы. Все 922 отслеживаемых файла сохранили SHA при аудите.
Полная общепроектная приёмка в этом документарном этапе не выполнялась.

Команды воспроизведения из корня проекта; выходной файл должен быть новым:

```powershell
.venv/Scripts/python.exe -X utf8 -B -m pytest -q -p no:cacheprovider -p scripts.native_audit tests/test_de441_reader.py tests/test_de441_reader_audit.py
.venv/Scripts/python.exe -X utf8 -B -m scripts.assess_de441_reader --output .tools/reader-card-replay/reader.json
```

Аудитор сохраняет SHA исходников и трёх входов: `de441-reader-inputs.zip`,
`nominal-jpl440-inputs.zip`, `offline-sources-validation.json` в `docs/`.
Для этого этапа отдельно сохранён локальный файл
`.tools/card333/verified/execution-manifest.json`: ревизия, чистота дерева,
версии, SHA зависимостей и файлов во время повтора. CLI читателя сам этот
дополнительный manifest не создаёт; его собственные SHA находятся в JSON аудита.
Одиночная стоимость прогона не является сравнительным benchmark.

**Итог:** цепочка «первичный формат → относительный вектор → реализация →
модельные проверки и сверка чтения» прослеживается. Проверка ошибки нового
интегратора здесь `NOT_APPLICABLE`: интегратор не менялся и не запускался.
Наличие десяти лет коэффициентов не квалифицирует симуляцию на десять лет;
точность между проверенными эпохами и истинная астрономическая погрешность
не установлены этой карточкой. Старые отчёты и неуспехи сохраняются.
