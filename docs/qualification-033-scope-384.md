# Кандидат0.3.3: границы следующей квалификации

30 октября2026. Решения по будущим этапам375/380; годовые и Q2 расчёты здесь
не разрешаются. [План382](qualification-033-plan.md) и все прежние evidence

## Годовой профиль375 в новой среде

Старый375 — результат своего source/native/environment. Его строгий gate
остаётся прежним. Архив исходников подтверждает историю, не сегодняшний solver.
Новый fingerprint не обязан равняться старому: версии приложения, native
и явно записанные thread settings действительно изменились.

Предлагается отдельный successor protocol для candidate033 с пятью разделами:

| Раздел | Проверка и смысл |
|---|---|
| История375 | Старые receipt/protocol/NPZ/raw SHA и источник каждого исторического результата; read-only replay, без новой аттестации |
| Новая численная точность | Свежие candidate Python/Rust Strict20/Strict10/holdout, реальные native calls и свежий независимый scalar-EIH/body-axis-J2 RK45 двух уровней; источники и окружение зафиксированы до запуска |
| JPL | Тот же SHA-проверенный DE441 cache и корректное совпадение IC, SSB/EclipticJ2000, JD2461321.5TDB, SI. Остатки показывают также отличие модели, не только solver error |
| Критерии | Дословно все научные criteria375, без исключения неудобных тел, Standard FAIL или подбора фазы.125epochs/9holdout, Strict rtol3e-14, atol.001m/1e-9m/s, dt3600, пакеты20/10 |
| Совместимость | Отдельные source-bound исполнения accepted032 и candidate033 в их настоящих средах. Сравнить raw states/epochs/packets и документы. Показать byte equality, численные разности и точный список metadata-различий; разные fingerprints не называть одинаковыми |

Основные старые научные пределы: каждое тело <10m/<1e-4m/s относительно
независимого reference; Earth–Moon <.1m/<1e-5m/s; reference sensitivity
<1m/ .1m; residual применимой модельной энергии <1e-10. JPL отдельно
<10km/тело и <1km Earth–Moon. Остальные sensitivity/sandbox criteria берутся
из original375 JSON без изменений. Newton без PN/J2 не считать тем же профилем.
Для EIH нужны соответствующие Noether/model diagnostics, а не одна Newton E.
Смешанные PN–figure члены по-прежнему отсутствуют; инварианты интерпретируются
в рамках принятого порядка модели, а не точной общей теории относительности.

**Открытый вопрос:** исходный375 требовал identical environment/native и
bitwise accepted032 comparison. Этот контракт не выполнен новой средой и
не становится PASS. Successor protocol должен явно отделить новую научную
точность от cross-version compatibility. Старые numerical tolerances не
переносятся произвольно на новый cross-environment regression gate.
Любое небитовое различие потребует объяснения и отдельного решения о допуске;
только ожидаемые metadata-различия можно заранее перечислить как таковые.

До годового запуска требуется утвердить successor scope и способ оценки
совместимости. Затем минимально адаптировать существующий375 assessor и
создать новый gate только по реально полученному receipt. Не заменять
CURRENT_RECEIPT_SHA и не отключать старые source/environment checks заранее.
Годовые jobs в384 запрещены независимо от результата Newton-проверки.

## Монотонность двух Q2-фигур380

Исходный380 — синтетический научный протокол, а не самостоятельная полная
release acceptance. Его `empirical_tolerance_convergence` — обязательная
проверка: standard–fine должно быть меньше coarse–fine. Worker первоначально
остановился именно на её отказе. План0.3.3 перенёс критерии380 без исключения.
Поэтому полная квалификация двух-Q2 по этим критериям сейчас **FAIL**;
автоматического release waiver нет. Три исторических packet FAIL сохраняются.
Отдельная continuous convergence их не отменяет. Общий release scope остаётся
UNRESOLVED до решения владельца; это не утверждение фундаментального закона
монотонности ошибки в binary64.

Рекомендуемый вариант для обсуждения: сохранить две Q2 как явно учебный
экспериментальный режим; отдельно утвердить будущий прикладной допуск с новым
именем и областью применения. Старый380 не переименовывать в PASS.

Предлагаемый будущий прикладной критерий должен до новых результатов задать:

- Физическую область, фиксированные IC/горизонт/эпохи/пакеты, наблюдаемые
  величины и внешний бюджет допустимой ошибки B_app, выбранный по назначению
  программы, а не по уже увиденным числам380.
- Независимый reference, оценку его чувствительности U_ref и проверку
  достаточного разрешения относительно B_app. Разность двух уровней RK45 —
  эмпирический показатель, не строгая математическая верхняя граница.
- Заранее определённое правило сравнения measured error и U_ref с B_app;
  никаких новых чисел B_app здесь не назначается.
- Отдельную оценку арифметического шума: точные повторения в frozen среде,
  независимый пересчёт наблюдаемых и заранее заданные precision contrasts.
  Нельзя объявлять весь немонотонный остаток roundoff без доказательств или
  вычитать шум для превращения старого FAIL в PASS.
- Прежние применимые gradient/reaction/E/P/L/qnorm gates, same-packet
  persistence, исходники/native SHA и воспроизводимость. Эти проверки
  необходимы вместе с reference, а не вместо проверки орбитальной ошибки.

Численные пороги, новая IC-выборка и release exemption не утверждены.
**Блокер владельца:** выбрать заявляемую область0.3.3 и необходимость такого
отдельного протокола.384 не меняет оригинальные380 criteria и не запускает
его полную повторную матрицу. Эти вопросы не блокируют независимый Newton376.
