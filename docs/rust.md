# Rust-ядро и прямой Python-модуль

Ядро расположено в `rust/solar_core`, Python-реализация сохранена.
Перенесены взаимная гравитация, Velocity Verlet, энергия, импульс,
угловой момент и центр масс. Орбитальные параметры пока остаются на Python.

Тела Rust используют трёхкомпонентные массивы `f64`; входное состояние
заимствуется через срез, а расчёт возвращает собственный массив тел.
Ошибки возвращаются как `Result`, а не аварийное завершение внутри ядра.
Ускорение конца шага переиспользуется в следующем шаге.

## Сборка и проверка на Windows

```powershell
& "$env:USERPROFILE\.cargo\bin\cargo.exe" test --manifest-path rust/solar_core/Cargo.toml
.\.venv\Scripts\python.exe -B examples/compare_rust.py
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider
```

Скрипт сравнения собирает release-версию, передаёт начальные состояния
пакетом и сравнивает пять сценариев на 8000 шагах. Результаты записываются
в `docs/rust-comparison.json`. Допуски расхождения положений и скоростей:
1e-9 соответствующих начальных относительных масштабов пары.
Время Rust включает запуск процесса, JSON и расчёт; это единичный замер,
не строгий benchmark. Компиляция в него не включается.

Интеграционные pytest-проверки пропускаются, если release-программа ещё
не собрана. Python-тесты доступны независимо от установки Rust.

## Инструменты и ограничения

Для первого этапа выбран `stable-x86_64-pc-windows-gnu` с минимальным
профилем, без изменения PATH. Стандартная установка находится в
`%USERPROFILE%/.cargo` и `%USERPROFILE%/.rustup`.
[Документация rustup для Windows](https://rust-lang.github.io/rustup/installation/windows.html)
описывает различия GNU и MSVC; дополнительные нативные библиотеки
могут потребовать отдельные инструменты.

JSON-программа сохранена для сравнения. Для обычного пакетного расчёта
теперь доступен прямой модуль PyO3 без отдельного процесса.
Физическая модель прежняя: точечные массы, фиксированный шаг, без контактов.

## Прямой модуль PyO3

На этом компьютере модуль уже установлен. Для повторной сборки:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,native]"
.\.venv\Scripts\python.exe -B scripts/build_native.py
.\.venv\Scripts\python.exe -B examples/compare_native.py
```

При чистой установке Windows GNU без ассемблера перед сборкой выполнить:

```powershell
.\.venv\Scripts\python.exe -B scripts/setup_gnu_tools.py
```

Этот вспомогательный скрипт требует Python 3.14, загружает официальные
MSYS2-пакеты с проверкой SHA256 и распаковывает инструменты/лицензии
в `.tools/msys2`. Список версий, URL и хешей — `.tools/msys2/packages.json`.
Можно использовать собственные GNU-инструменты или MSVC вместо bootstrap.

### Использование

```python
from solar_simulator.simulation import sun_earth
from solar_simulator.rust_backend import evolve

initial, period = sun_earth(0.6)
result = evolve(initial, dt=period / 4000, steps=8000)
```

Нативный низкоуровневый API:

```python
import solar_native
positions, velocities = solar_native.evolve(
    masses=[1.0], positions=[[0.0, 0.0, 0.0]],
    velocities=[[1.0, 0.0, 0.0]], dt=2.0, steps=3,
)
# positions: [[6.0, 0.0, 0.0]] (вложенные последовательности)
```

Для массовых расчётов передавать несколько шагов за вызов. Списки
копируются на входе и выходе; прямой NumPy/zero-copy API пока отсутствует.
Каждый расчёт имеет собственное состояние и не меняет входные тела.
Имена тел сохраняет Python-обёртка; для физики Rust достаточно масс и массивов.

На время вычислений используется [Python::detach](https://pyo3.rs/main/parallelism.html).
Модуль проверен с CPython 3.14t, не включает GIL при импорте и выполняет
независимые расчёты из двух потоков. Это не делает один расчёт многопоточным.
Во время копирования входных списков их не следует менять из другого потока.

### Распространение и ограничения

```powershell
.\.venv\Scripts\python.exe -B scripts/build_native.py --wheel
```

Wheel сохраняется в `.tools/wheels`. Текущая проверенная сборка:
`cp314-cp314t-win_amd64`. Для обычного Python с GIL или другой ОС/архитектуры
нужна соответствующая сборка. Wheel проверен в чистом окружении.

`examples/compare_native.py` записывает результаты в
`docs/native-comparison.json`. Замер включает преобразование данных и
один вызов; первый сценарий также включает импорт модуля. Это разовые
измерения, не обещание фиксированного ускорения.

При отсутствии модуля обёртка сообщает команду сборки; скрытого перехода
на Python нет. При запуске тестов без установленного модуля нативные
проверки пропускаются. Здесь все 108 тестов выполнялись без пропусков.
Физическая модель остаётся прежней; графические примеры по умолчанию
пока используют Python. Управление запуском, отмена и UI — отдельный этап.

## Радиусы и выдача снимков

Обычный evolve сохраняет радиусы как метаданные, но не обрабатывает контакт.
Для сфер используйте contacts.run_until_contact с backend="rust" или "python".
runner.sampled_states выдаёт снимки после блоков по 20 шагов; этот режим
только для точечных тел. Графические примеры поддерживают --backend rust.

## Контактный API

```python
from solar_simulator.contacts import run_until_contact
result = run_until_contact(bodies, dt=0.1, steps=1000, backend="rust")
# result.bodies, result.time, result.contact
```

Модуль принимает радиусы отдельным массивом; индекс события соответствует
порядку входных тел. Всё вычисление отсоединено от Python. Копирование
массивов происходит один раз на входе и выходе. Контакт может возникнуть
внутри последнего шага; его время возвращается от начала запуска.

Rust использует независимый поиск корней через производные и бисекцию,
Python — NumPy. Обе реализации проверены на одних сценариях, включая
независимое событие SciPy. Сам физический интегратор не менялся.
После изменения исходников выполняйте scripts/build_native.py для пересборки.

## Реакция на контакт

```python
from solar_simulator.impacts import resolve_contact
impact = resolve_contact(result.bodies, result.contact.first,
                         result.contact.second, restitution=0.5, backend="rust")
# impact.bodies, impact.dissipated_energy, impact.impulse
```

Rust получает массы, позиции, скорости и радиусы, рассчитывает импульс
без Python и возвращает новые скорости с энергетическими потерями.
Имена/позиции/радиусы сохраняет обёртка. Низкоуровневая функция:
solar_native.resolve_contact(masses, positions, velocities, radii,
                             first, second, restitution).
Неупругость — потеря кинетической энергии, а не слияние. Трение и вращательная динамика не реализованы.

## API версии 0.2

`simulate_collisions(..., backend="rust")` выполняет весь цикл повторных
отскоков одним PyO3-вызовом. Детектор Rust выделяет только входящие корни,
исключая расходящееся касание после удара. Возвращаются состояние, время,
список событий и сумма потерь. Модуль освобождает интерпретатор на время
расчёта; независимые расчёты проверены в потоках.

Низкоуровневый вызов:

```python
solar_native.simulate_collisions(masses, positions, velocities, radii,
                                dt, steps, restitution, max_events)
# positions, velocities, time, [(first, second, time), ...], loss
solar_native.diagnostics(masses, positions, velocities, spins=None)
```

Spin — внутренний угловой момент в кг·м²/с, учитывается в диагностике L,
но не влияет на движение центров. При стандартном массивном evolve
Python-обёртка сохраняет исходные spin; JSON-протокол Rust принимает и
возвращает поле spin (по умолчанию нулевое). Для нативной диагностики
ненулевые spin нужно передать явно. Модель слияния и её цикл реализованы
на Python; backend=rust использует нативные движение и остановку при
контакте, но не делает ложного обещания целиком нативного слияния.

Переносимая сборка `scripts/build_portable.py` содержит CPython и оба
wheel. Она не зависит от Cargo или исходной .venv во время запуска.
Подготовка Windows-сборки и проверка после распаковки описаны в
[руководстве](user-guide.md). Номера версий Python/Rust-пакетов — 0.2.0;
исторические измерения и wheel 0.1.0 выше относятся к прежним этапам.
