# Планетный профиль для первой песочницы

14 октября 2026, изменения121–122. [Протокол](sandbox-models-protocol.md)
задан до запуска; пользователь разрешил проверку предварительных целей
10км для каждого из10тел и1км для Moon−Earth с сохранением неуспехов.
Новые физические эффекты и подгонка начальных условий не вводились.
[Полные измерения и SHA](sandbox-models-validation.json).

## Результат контролируемого сравнения

Одинаковые10тел, JD2461321.5TDB, EclipticJ2000, SSB, SI, год31557600с,
45 эпох Earth/Moon и13 остальных тел. Внешние планеты — точечные модели
системных барицентров; их спутники дополнительно не включены.
DOP853/per-body/Earth–Moon relativepair: rtol1e-13, atol1e-3м/1e-9м/с;
контроль rtol3e-14. Таблица — ядро Rust, Python проверен отдельно с теми же
критериями. Остатки — максимумы на заданной сетке, не гарантии между эпохами.

| Модель | Mercury/JPL, м | Earth/JPL, м | Moon/JPL, м | Moon−Earth/JPL, м | Физические цели |
|---|---:|---:|---:|---:|---|
| Newton | 154006 | 55758 | 59718 | 21724 | Не прошли |
| EIH1PN | 312 | 392 | 25329 | 25617 | Не прошли: Moon и Moon−Earth |
| EIH+FixedSunJ2 | 208 | 389 | 25327 | 25617 | Не прошли: Moon и Moon−Earth |
| EIH+FixedSunJ2+FixedEarthJ2 | 208 | 169 | 672 | 643 | Прошли все10тел и Moon−Earth |

EIH устраняет основную измеренную разницу планетных орбит в этой постановке,
но ухудшает лунный остаток. Нельзя обещать монотонный выигрыш от каждого эффекта.
SunJ2 меняет Mercury-траекторию до124.7м относительно EIH и уменьшает её
максимальный остаток312→208м; у Venus остаток232.6→257.5м вырос.
EarthJ2 меняет Moon-траекторию до24.7км и уменьшает Moon−Earth остаток
25.6км→643м. Малую разницу Moon−Earth между EIH и EIH+SunJ2 на миллиметрах
нельзя считать подтверждённым улучшением: она меньше численной чувствительности.

У последнего профиля максимальные остатки JPL: Sun219м, Mercury208м,
Venus257м, Earth169м, Moon672м, Mars571м, Jupiter273м, Saturn31м,
Uranus17м, Neptune65м. Ни одно тело не исключалось из физического критерия.
Прежние неуспехи сохранены в JSON с отдельными булевыми проверками.

## Независимая численная проверка и стоимость

Reference — RK45 с независимо кодируемыми EMB+Moon−Earth и полем FixedJ2
в осях тела. EIH — отдельный scalar oracle в scripts/validation/eih_scalar.rs,
не runtime solar_core. Два уровня rtol1e-13/maxstep1800с и3e-14/900с,
AU/year, atol1e-17; исходники проверены по SHA до/после свободного расчёта.
Сравнение Python/Rust не используется как независимый эталон.

| Модель | Максимум разности с reference, Rust, м | Moon−Earth/reference, м | Время Python/Rust, с | Время двух reference, с |
|---|---:|---:|---:|---:|
| Newton | 0.0685 | 0.0570 | 0.607 / 0.386 | 14.04 |
| EIH1PN | 0.0578 | 0.0401 | 1.398 / 0.407 | 14.60 |
| EIH+SunJ2 | 0.0560 | 0.0491 | 2.035 / 1.063 | 26.97 |
| EIH+SunJ2+EarthJ2 | 0.0709 | 0.0733 | 2.574 / 1.518 | 40.30 |

Для Python максимум всех профилей<0.073м. Чувствительность reference
в абсолютных координатах до0.0919м, Moon−Earth до0.00374м. Все прошли
заданные численные10м/1e-4м/с и Moon−Earth0.1м/1e-5м/с.
Runtime rtol1e-13→3e-14 меняет позиции до0.0197м; Python/Rust до0.0154м.
Сантиметровое согласие не является сантиметровой физической точностью:
сами reference чувствительны к выбору уровня, а модель/JPL имеет остатки сотни метров.

Энергия соответствует Newton или EIH/Noether, плюс постоянный потенциал
FixedJ2. Максимальные относительные дрейфы<1e-14, заданный предел1e-10 прошёл.
Для моделей без фигур соответствующий J также прошёл1e-10. У FixedJ2 оси
удерживаются постоянными; орбитальный J может обмениваться с ними, поэтому
его сохранение не является критерием. В EIH+J2 отсутствуют смешанные PN-члены
фигуры; это усечённая модель, не полная релятивистская динамика протяжённых тел.

Времена одиночные и включают диагностику45 эпох, без GUI/загрузки данных.
Усиление модели стоит дороже; оптимизация в этом блоке не выполнялась и
порог точности ради скорости не менялся. Версии Python/NumPy/SciPy,
компилятора oracle, настройки и SHA записаны в JSON. Повторение:

```powershell
.venv/Scripts/python.exe -X utf8 -B scripts/assess_sandbox_models.py
```

## Готовый режим и добавление пользовательского тела

В исходной GUI-версии нажми «Солнечная система: EIH + J2». Кнопка создаёт
новый опыт с проверенным начальным состоянием и fixed Sun/Earth J2.
Предыдущий опыт сначала сохрани, если он нужен. Обычный сценарий по-прежнему
Newton: физика не меняется молча. API: `application_profiles.solar_sandbox`.

На паузе, после окончания пакета, нажми «Добавить тело…». Шаблоны
«Учебная планета: масса Земли» и «Учебная звезда: масса Солнца» задают
номинальную массу из прежних учебных констант. Это не данные JPL и не орбита.
Имя, массу, все3координаты и3скорости можно изменить. Векторы по умолчанию
пусты: введи их явно в текущей инерциальной системе в метрах/м/с.
Относительная проекция графика не изменяет систему ввода.

Новое тело точечное, radius=0; масса и состояние определяют его взаимодействия
тем же алгоритмом, названия/шаблоны не выбирают особую формулу. Применение
сначала сохраняет parent+child bundle, затем переключает на новый старт t=0.
Отмена/ошибка записи сохраняют старый опыт и файл. Новый child имеет
origin=None: прежнюю квалификацию JPL на него переносить нельзя.

Совпадающие положения, повторное имя, NaN/Infinity, недопустимая EIHскорость,
слабое поле и область внешней J2 проверяются существующим ядром.
Радиусы реальных пользовательских звёзд/планет, поверхность, разрушения и
автоматический выбор круговой орбиты не реализованы. Вращение/заданные во
времени Q2 пока запрещают этот редактор. [Правила веток](sandbox-experiments.md).

## Проверки, неуспехи и ограничения

Базовый JPL reference schema1 не имеет поля gm_sha256: первый preflight
ошибочно ожидал его и завершился KeyError до интеграции. Проверка исправлена
через подтверждённый base_origin+dataset SHA и resolved reference;
старые JSON/пороги не менялись. После добавления явных версий/settings в
новый JSON сравнение повторено целиком, результаты критериев прежние.

Реальный Tk journey проверил шаблоны, недопустимые входы, отмену, ошибку
атомарной записи, добавление11-го тела, доступность в списке графика,
сохранность parent и точное совпадение с тем же headless опытом/продолжением.
Старый редактор и геометрия контролов прошли проверки. Полный прогон:
1299 Python/157.53с,17Rust и cargo fmt обоих модулей прошли.
После полного прогона уточнён только testcase границы J2: расстояние1e8м
выбрано внутриRsun, но вне отказа EIHweakfield; отдельно проверен текст отказа
J2. Уточнённый GUI-тест прошёл за1.57с; runtime после full не менялся.

Физические критерии достигнуты только для фиксированного набора, исходного
состояния, года и указанной сетки. Нет полной ориентации/вращения, приливов,
астероидов, высших гармоник, новых столкновений, ошибок наблюдений/оценок масс
или гарантии между эпохами. Дополнительные эффекты добавлять по измеренной
необходимости. Сравнение не доказывает единственную причину каждого остатка.

Первичный источник полноты моделей и соглашений:
[Park et al.,2021, AJ161:105, DOI10.3847/1538-3881/abd414](https://ssd.jpl.nasa.gov/doc/Park.2021.AJ.DE440.pdf),
разделы2.3/3.1/3.2; [EIH action](https://fiteoweb.unige.ch/~maggiore/GWVol1/EIHLagrangian.pdf)
для лагранжиана. Современные DE440 и более длинные DE441 не отождествляются;
сохраняется закреплённый DE441-набор проекта. Кольцо в этот профиль не входит;
его прежние неуспехи420 и KBO-ограничения528 сохраняются.

Новая GUI-функциональность доступна в исходном проекте. Portable ZIP
от12октября не пересобиралась и её не содержит. GitHub не изменялся.
