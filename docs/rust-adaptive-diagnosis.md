каждая из двух проверенных аналитических альтернатив по отдельности

## Метод и независимость

Сохранённые девять траекторий335 повторно не интегрировались. SI, два
ньютоновских точечных массивных тела, наклонные3D-оси, t0=0, два периода,
6×82 и3×60 эпох. SHA кода/входного JSON/NPZ и начальные компоненты/массы/эпохи
проверены; все прежние поэпоховые ошибки и float64-экспорт Decimal-эталона
совпали точно. Ошибка считается из точной разности записанных float64
компонент в Decimal110; неопределённость существующего oracle70/100 ниже
1e-6м/1e-12мс. Источники и область f/g-решения: [протокол156](kepler-phase-protocol.md).

Переиспользована существующая `assess_kepler_phase.references`: сравнение
exact-IC решения с однократно округлённой начальной относительной r/v,
а отдельно — с суммой округлённых native GM. Начальные данные и модель
приёмки не заменялись этими альтернативами. Для каждого отдельного бюджета
B и исходного максимума E обратный треугольник даёт max(0,E−B).
Итоговые binary64-границы дополнительно округлены консервативно вниз.

Например, для82:e=.95 исходная ошибка4.411367м, IC-бюджет0.039274м,
GM-бюджет0.000761м. Нижние границы после каждого отдельного объяснения:
4.372094м и4.410606м; обе значительно выше0.1м.
Даже пограничный апоцентр остаётся выше критерия:0.104408м и0.104502м;
нижние границы ошибки скорости1.333245e-6 и1.334447e-6м/с выше1e-6.

Это исключает две конкретные причины **по отдельности** как достаточное
объяснение отказов. Их бюджеты не складывались. Они не охватывают всё
округление стадий, подготовку переменных и вычисление сил; по этому опыту
нельзя объявить полный силовой RHS точным или установить виновную операцию.

## Геометрия расхождения

Использована линейная проекция δr на аналитическую скорость v:
δt=(δr·v)/(v·v), δr_parallel=δt·v, δr_normal=δr−δr_parallel.
Точные3D-примеры проверяют знак, ортогональность и поворот знаковой
перестановкой. Нулевой остаток имеет неопределённую долю, записанную как null.

В худшей по положению точке каждого из четырёх FAIL доля вдоль скорости
превышает0.9999997. Для82:e=.95 нормальная компонента0.000109м при общей
ошибке4.411367м, линейно эквивалентное δt≈−23.716мкс.
Эта величина описывает геометрию; причины накопления ошибки она не определяет.
Все временные границы335 сохранены; эталон не сдвигался, проекция не вычиталась
при проверке точности. Все эпохи, а не только худшая, сохранены в JSON.

## Проверки, стоимость и сохранённый отказ стенда

Первый диагностический запуск остановился через15.413с: новый caller
вызывал `decimal_relative` при стандартных28 цифрах вместо требуемых110.
Guard точного воспроизведения ошибок335 обнаружил расхождение; частичный
JSON и исходный dirty-снимок сохранены в `.tools/rust336/diagnosis*`.
Исправлен только новый caller, добавлена проверка при ambient9/28/110.
Эталон, Rust и исходный отчёт335 не менялись.

Исправленный полный анализ занял130.774с; 47 связанных Python-тестов прошли
за2.92с,0skip, включая10 новых. Есть отказы при изменении исходника/NPZ,
неполном receipt и попытке перезаписать результат. После анализа добавлены
только дополнительные тесты целостности; их SHA записан отдельно.
Это стоимость пересчёта аналитических чувствительностей, не benchmark
интегратора. Новый Rust build, полный production-набор и portable не выполнялись.

```powershell
.venv/Scripts/python.exe -X utf8 -B -m scripts.diagnose_rust_adaptive --output .tools/adaptive-diagnosis-replay/result.json
```

Команда требует неизменных входов335 и соответствующих SHA рабочих исходников
(включая ранее документированные CRLF Cargo-файлов). Выход должен быть новым.
Она не устанавливает зависимости и не использует сеть/JPL/Consensus.

## Решение и следующий шаг

Рабочее приложение, Rust-прототип, допуски, эталон и версия0.3.0 прежние.
Допуск прототипа в runtime/10тел/год остаётся закрыт. Критерии не ослаблены.
Существующие159–179 уже исследовали sum/carry/caps и независимый IAS15;
эти выводы учитываются, новый перебор тех же вариантов не предлагается.

Следующий ограниченный шаг337 — диагностическая запись арифметики стадий
и принятых обновлений именно Rust-контроллера. Сначала доказать, что запись
не меняет исходные траектории/границы; затем измерить локальные потери
округления относительно точной арифметики сохранённых операндов. Не менять
приёмку, не приписывать локальным потерям всю глобальную фазовую ошибку
и не выбирать новый метод или набор допусков без отдельного обоснования.
