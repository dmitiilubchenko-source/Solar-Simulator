### Норма DOP853 — не только rtol

При `scale_i = atol_i + rtol max(abs(y_i), abs(y_new_i))` сначала вычисляются
масштабированные оценки пятого и третьего порядков. Для каждого блока из
трёх компонент обозначим их евклидовы нормы через `a` и `b`. Текущий критерий:

```text
block = abs(h) a (a / hypot(a, 0.1 b)) / sqrt(3)
error = max(blocks, optional_work_error)
```

При обоих нулевых оценках вклад равен нулю. Используются устойчивые `hypot`
и явное отклонение неконечных значений. Для скаляра работы деления на sqrt(3)
нет. Принятие в текущем SciPy — строго `error < 1`; SAFETY=0.9,
MIN_FACTOR=0.2, MAX_FACTOR=10, показатель коррекции шага −1/8.
После отклонённой попытки немедленный рост принятого шага ограничен.

Общий RMS по 6N переменным может скрывать ошибку отдельного тела.
Даже два независимо вычисленных максимума `a` и `b` не заменяют максимум
совместного выражения: большие оценки могут принадлежать разным блокам.
Поэтому одного пользовательского `State.error_norm` недостаточно для
прямого сохранения нашего критерия в рассмотренном DOP853.

Выбор первого шага также фиксируется. У нынешнего SciPy начальная оценка
использует общую норму; текущие тесты автоматического шага проверяют точность,
а не равенство внутренних шагов при добавлении неактивных уравнений.
Не обещать побитную идентичность Rust/Python: порядок суммирования и сетка
пакетов могут изменить накопленное округление. Независимые критерии обязательны.

## Проверенные готовые реализации

[Машиночитаемая сверка](rust-adaptive-source-review.json) фиксирует точные
версии, официальные архивы, SHA-256, лицензии и файлы/строки доказательств.
Архивы сверены с checksum crates.io; это проверка происхождения кода,
не математическая аттестация библиотек. Пакеты не устанавливались.

| Кандидат | Подтверждено в исходниках | Ограничение для прямой замены |
|---|---|---|
| `ode_solvers 0.6.2` | DOP853, Apache-2.0 | Скалярные atol/rtol и общий RMS; граница и контроллер закрыты внутри `Dop853` |
| `ivp 0.6.0` | Векторные допуски, Apache-2.0 | Общий RMS внутри `solve`; контроллер хранится в локальных переменных, готового пошагового состояния этот метод не предоставляет |
| `differential-equations 0.7.0` | Векторные допуски и публичные init/step/set_h, Apache-2.0 | DOP853 сводит две оценки по всему состоянию; отдельный max-component контроль другого семейства методов к DOP853 не относится |

У последнего DOP853 на принятом шаге также вычисляются три дополнительные
RHS-стадии для интерполяции. Наличие пошагового API не отключает эту работу.
Это наблюдение по исходнику, не измерение замедления библиотеки.
Переключение семейства метода ради другого error-control было бы отдельным
численным изменением. Простое совпадение названия DOP853 недостаточно.

Ни один кандидат не прошёл **конкретный критерий прямой замены**. Это не
оценка общего качества библиотек. Численная точность, сборка в нашей среде
и быстродействие этих трёх пакетов здесь `INCOMPLETE`: они не запускались.

## Решение и следующий ограниченный стенд

Не добавлять сейчас новую рабочую Cargo-зависимость и не строить универсальную
систему трейтов интеграторов. Для следующего стенда предпочтителен узкий
перенос уже используемого контроллера: зафиксированные исходники установленной
SciPy 1.18.1 плюс наш `PerBodyDOP853`, с сохранением уведомлений BSD-3-Clause.
SHA `rk.py`, `common.py`, `dop853_coefficients.py` и файла лицензии записаны
в JSON сверки. Это рекомендация для эксперимента, а не готовый Rust-порт.

Переносить только стадии, оценку ошибки и контроллер в собственный сеанс
с буферами `Vec<f64>`; вызывать существующие Rust-силы непосредственно.
Ошибки сил передавать явно, без молчаливого fallback и без повторного
Python-callback на каждой стадии. Сначала изолированный headless-стенд;
публичный FFI, GUI и новые форматы сохранения сейчас не нужны.

Первичные описания метода: [Hairer/Wanner DOP853](https://www.unige.ch/~hairer/prog/nonstiff/dop853.f)
и [документация SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.DOP853.html).
Интернет-страница SciPy сейчас показывает 1.18.0; фактические установленные
байты 1.18.1 закреплены отдельно и не подменяются ссылкой `latest`.
