# Общий шаблон небесного тела

Планеты, спутники и астероиды используют один тип `Body` и одно физическое
ядро. Чтобы обычное точечное тело участвовало в расчёте, достаточно имени,
массы, трёх координат и трёх компонент скорости. Все величины — в СИ:
килограммы, метры и метры в секунду. Имя не выбирает формулу гравитации:
все тела влияют друг на друга, а не движутся по заранее нарисованным орбитам.

Минимальный пример своего опыта:

```python
from solar_simulator.simulation import Body
from solar_simulator.vector3 import Vector3
from solar_simulator.experiment import Settings, create_experiment, advance

bodies = [
    Body("Primary", 1e24, Vector3(0, 0, 0), Vector3(0, 0, 0)),
    Body("Companion", 1e20, Vector3(1e8, 0, 0), Vector3(0, 817, 0)),
]
experiment = create_experiment(bodies, Settings(60, integrator="dop853"))
result = advance(experiment, 1440)  # Одни сутки
```

Это произвольные учебные начальные данные, а не подтверждённая орбита
реального спутника. В GUI таблица тел позволяет задавать свои параметры;
сохранение хранит полный список тел. Контактный радиус и passive spin нужны
для отдельного режима контактов. Они не требуются точечному телу DOP853.

## Почему реальные объекты всё равно проверяются отдельно

У всех исходных состояний должны совпадать дата, система координат,
единицы и точка отсчёта. Например, вектор астероида относительно Солнца
нельзя напрямую смешать с положением Земли относительно общего центра масс
Солнечной системы. Также GM целой системы спутников нельзя выдать за GM
отдельной планеты. Правильные данные важнее названия объекта.

Для проверенных расширений есть общий `SupplementSpec` и загрузчик
`decode_body_dataset` в `solar_simulator/perturbers.py`. Контракт содержит
файл, хеш данных, проверенный родительский набор, происхождение GM/векторов
и список идентификаторов. Каждый элемент JSON имеет один формат:

```json
{
  "id": 2000001,
  "name": "Ceres",
  "gm_m3_s2": 62628888644.40994,
  "position": [0, 0, 0],
  "velocity": [0, 0, 0]
}
```

Нулевые векторы здесь показывают только структуру; реальные значения берутся
из закреплённого файла. Масса внутри `Body` вычисляется как `GM / G`.
Загрузчик не принимает дубли, неверный порядок/идентификатор, NaN,
булевы числа вместо физических величин, чужие источники и будущие траектории.
При чтении встроенного файла проверяется его SHA-256. Подключение очередного
проверенного набора не требует новой функции гравитации для каждого тела.
Сценарий `solar-system-asteroids-catalog` добавляет тем же контрактом 327
недостающих астероидов к прежним 27 телам: всего 354, из них 343 астероида.
Состав и начальные состояния уже существующих тел сохраняются побитно.
[Годовая проверка полного каталога](asteroids-catalog.md).

Сценарий `solar-system-kuiper` добавляет к этим 354 телам все 30 отдельных
KBO выбранного каталога DE441 тем же `SupplementSpec`. Система Плутона уже
учтена в родительском наборе; ни дополнительный Плутон, ни кольцо не добавляются.
[Данные и проверка объектов Койпера](kuiper.md).

Для своих произвольных экспериментов регистрация набора JPL не нужна:
можно создавать `Body` напрямую. Регистрация нужна, чтобы встроенный
сценарий имел проверяемое происхождение, воспроизводился офлайн и сохранял
совместимость с закреплёнными профилями формы/ориентации.

## Дополнительные физические свойства

Форма и вращение описываются отдельно от обычного тела. Осесимметричное
поле `FixedJ2` универсально: задаются имя источника, J2, опорный радиус и ось.
Готовый профиль Земли/Луны дополнительно использует конкретные данные об
ориентации. Это специальный вход модели, а не отдельная формула для каждой
планеты. [Ограничения формы и ориентации](orientation.md) и
[пример трёх астероидов](asteroids.md) показывают эту разницу.

Кольцо добавляется отдельным модулем kuiper_ring через тот же SupplementSpec.
Закреплены шесть начальных снимков: 36/72/144 точки и две фазы.
Во всех случаях сохраняются прежние 384 тела и одинаковый суммарный GM
MA8201–MA8236. Отрицательные ID и имена точек внутренние, не SPK ID JPL.
[Допущения и фактическая проверка кольца](kuiper-ring.md).
