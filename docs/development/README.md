## Ключевые части кода

| Что изучаем | Документация рядом с кодом |
|---|---|
| Типы состояния, настройки, расчёт, сохранения и GUI | [Python-пакет](../../src/solar_simulator/README.md) |
| Собственные Rust-силы и фиксированный Verlet | [solar_core](../../rust/solar_core/README.md) |
| Вызовы Rust из Python и граница массивов | [solar_native](../../rust/solar_native/README.md) |
| Исследовательский адаптивный solver | [solar_adaptive](../../rust/solar_adaptive/README.md) |
| Короткая приёмка пользовательского цикла | [sandbox_checks](../../scripts/sandbox_checks/README.md) |

Rust-крейты уже имеют собственные каталоги; README поясняют реальные файлы,
API, команды и ограничения. У Python сохранены нынешние импорты и пути:
их изменение затрагивает научные source SHA и требует отдельной проверки.
Копий реализаций для удобства чтения нет.

## Рабочий цикл

[Ближайшая 0.3.2 и зависимости проверок](maintenance-032.md): конечный состав,
подтверждённые ограничения и условия завершения.

Конкретная задача и критерий → минимальная правка → относящиеся проверки →
оценка результата и стоимости → необходимое улучшение. Не требуется запускать
все исторические исследования после каждой правки интерфейса или README.

Команды проверок и их назначение — [здесь](../verification/README.md).
[Правила выпусков](../release-workflow.md) отделяют commit/push в dev от
приёмки main/тега. [Карта файлов](../project-inventory.json) — машинный реестр,
а не список документов, которые разработчик должен прочитать подряд.
