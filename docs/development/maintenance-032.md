# Ограниченный состав 0.3.2

25 октября 2026, изменение 368. Это план кандидата; принятая версия — 0.3.1.
Задача выпуска — понятная структура и надёжные проверки существующей песочницы.
Новые численные методы, физические эффекты и перенос runtime в Rust сюда не входят.

## Фактические зависимости команд

| Команда из корня проекта | Что выполняет и требует |
|---|---|
| `python -B scripts/check_suites.py python` | Явный CI-поднабор, реестр, ссылки. NumPy/SciPy/Matplotlib/pytest; native и Rust toolchain не обязательны. Автоматический setup pytest требует публичный архив исследовательских входов |
| `python -B scripts/check_suites.py desktop` | GUI/native-поднабор, настоящий Tk display, скомпилированный PyO3 и standalone Rust release, fmt/test Rust; пропуски отклоняются |
| `python -B -m scripts.sandbox_checks` | Старые научные SHA и сохранённый FAIL, новая короткая аналитическая задача Python/Rust, сохранение и продолжение. Требует native; новые эпохи JPL и годовой расчёт не выполняет |
| `python -B scripts/check_project.py --require-native` | Все Python-тесты, реестр, ссылки, Rust fmt/test. Требует desktop/native/standalone и публичные входы; любой skip означает отказ приёмки |
| `python -B scripts/check_suites.py adaptive` | Отдельный исследовательский набор и Rust adaptive с diagnostic-trace. В GitHub запускается только через ручной workflow с research=true |
| `python -B scripts/build_portable.py` | Собирает Windows runtime из установленной среды, wheel продукта/native, метаданных и разрешённых документов; это ещё не приёмка ZIP |
| `python -B scripts/check_portable.py <ZIP>` | Свежая распаковка, изолированный runtime, ссылки и пользовательские сценарии поставки. Версии и содержимое проверяются по реальному архиву |

`python` в таблице — интерпретатор настроенной среды; в Windows проекта это
`.venv/Scripts/python.exe -X utf8`. Точный состав CI: `check_suites.py <suite> --list`.
Установка и ограничения платформы — [reproducibility.md](../reproducibility.md).

Прямые зависимости приложения — NumPy, SciPy и Matplotlib
([pyproject.toml](../../pyproject.toml:11)). Установленная portable-цепочка
содержит 12 дистрибутивов: остальные нужны этим трём библиотекам.

## Находки и минимальные решения

**A — обязательных изменений ядра по этому аудиту команд не выявлено.**
Это не полная проверка архитектуры и не математическая верификация алгоритмов.

**B — исправлено покрытие быстрого CI.** Существующие 8 тестов подготовки
portable-документов и 6 тестов восстановления публичных входов не входили
ни в один CI-поднабор. Они теперь включены в python: исполняются настоящий
сборщик документов и проверки SHA/повреждения архива/сохранности старых файлов.
Новые тестовые слои, численные пороги и зависимости не добавлены.
Эта проверка документов не заменяет настоящую сборку и приёмку ZIP.

**B — общая подготовка исторических входов требует отдельной небольшой правки.**
[Autouse-fixture](../../tests/conftest.py:7) запускает восстановление семи файлов
для любого теста. В изолированной копии один `test_vector3.py` дал 38 ошибок
при отсутствии публичного архива, затем 38 PASS после добавления тех же публичных
ZIP/manifest. Рабочий кеш и архив проекта не изменялись. Это связанность тестовой
среды, не зависимость физического ядра от исследовательских данных.
В чистом checkout архив уже поставляется. Нужность сужения setup подтверждена;
это не блокирует текущий продукт. Минимальный будущий вариант — явный fixture
только у тестов, которые читают эти входы, с проверкой полного чистого запуска.
Существующий conftest закреплён историческим
[отчётом воспроизводимости](../sandbox-reproducibility-validation.json);
его изменение требует сохранить точные прежние байты и историческую проверку.
В 0.3.2 такая перестройка подготовки входов не включена.

**B — переносы ограничены воспроизводимостью.** Научные отчёты закрепляют
точные исходники и пути. Дальнейший перенос требует проверки потребителей и
старых снимков; массовая замена SHA нарушит смысл доказательств. Новые отчёты
должны закреплять необходимые зависимости, а не автоматически весь проект.

**C — сохраняем работающие границы.** CI/full acceptance/ZIP acceptance решают
разные задачи. Исследовательский adaptive запускается отдельно, runtime не
импортирует REBOUND. Общую абстракцию всех проверок, новый реестр зависимостей
или массовое перемещение кода вводить не требуется.

## Что закончить для кандидата

1. **Готово:** компонент приёмки и совместимые команды (366), меню и архив (367),
   уточнённое CI-покрытие (368). Ссылки и реестр должны проходить в чистом checkout.
2. **Далее:** подготовить согласованные Python/core/native метаданные 0.3.2,
   описание выпуска и свежие wheel/binary. Исследовательский crate не обязан
   получать номер продукта. До смены SHA-bound файлов сохранить прежние байты.
3. **До объявления готовности:** на окончательном кандидате выполнить полную
   source/native-приёмку без skip; собрать свежий ZIP/SHA и проверить его штатной
   командой после распаковки. Пройти сохранение → восстановление → продолжение,
   редактирование, запись/просмотр и сравнение в поставке; подтвердить отсутствие
   личных файлов. При изменении численной модели нужны её независимые проверки.
4. **Публикационное решение:** перечислить реальные результаты и оставшиеся
   ограничения, сохранить исходный FAIL. Отдельно согласовать main/тег с владельцем.

Не включены: новый интегратор IAS15, новые вращение/приливы/столкновения,
добавление тел, 3D, универсальные frameworks, переписывание старых научных отчётов
и обещание лучшей точности. Физические показатели имеют только ту область
применимости, которая измерена в [принятой квалификации](../release-031-validation.md).
Порядок выпуска — [release-workflow.md](../release-workflow.md).
