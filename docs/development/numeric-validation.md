# Числовые параметры физических объектов

Контракт укреплён в dev после 0.3.2. Формулы, интеграторы и схемы checkpoint
не изменены. Принятый ZIP 0.3.2 содержит прежнюю реализацию.

## Допустимые значения

- Встроенные `int` и `float` сохраняют тип и значение, включая знак нуля.
- NumPy integer переводится в Python `int` без усечения до float64.
- NumPy float16/32/64 переводится в Python `float` без потери значения.
  `longdouble` поддерживается только при размере не больше 8 байт;
  более широкая точность требует явного решения вызывающего кода.
- `bool`, `numpy.bool_`, complex, строки, Decimal и массив вместо скаляра
  отклоняются с `ValueError`. NaN/inf и целые вне конечного диапазона
  вычисления также отклоняются. NumPy datetime/timedelta не считаются физическими
  скалярами. Знаковые ограничения массы/радиуса сохранены.
  Прежний `max_step=+inf` в модельном API разрешён как отсутствие верхнего
  ограничения; бесконечные состояния/эпохи/допуски этим не разрешаются.

Границы: Body, Vector3, RigidFigure, RotationState, Settings, скалярные
операции Vector3, step, круговые сценарии и Python API контактов/native-моста.
Векторные входы вращения проверяются до преобразования массива в float:
это не позволяет смешанному списку скрыть bool как 0.0/1.0.
Численные массивы вращения остаются float64, как прежде.
Модельный `atol` по-прежнему допускает массив; более узкие ограничения
отдельных исследовательских API за этими границами не расширялись.
Это сохраняет прежнее округление больших целых моментов инерции при переводе
в float64. Нормализация float32 сохраняет уже имеющееся значение, не возвращает
потерянную ранее точность. Существующие пользователи NumPy-входов:
[начальные векторы](../../tests/test_anchored_reference.py:42) и
[модельный стенд](../../scripts/assess_core.py:92).

Счётчики/индексы и строковые параметры имеют собственные прежние проверки.
Низкоуровневое извлечение аргументов PyO3 не менялось; прикладные Python-вызовы
проходят собственную проверку до передачи в extension. Прямое редактирование
x/y/z после конструктора не является нормализацией ввода: Body отклоняет
неканонические компоненты при повторном создании, неизменяемость не добавлена.

## Проверки и воспроизводимость

[Регрессии входов](../../tests/test_numeric_validation.py),
[Python/native-цепочка](../../tests/test_numeric_native.py),
[побитовая сверка с прежними исходниками](../../tests/test_numeric_history.py).
Для поддерживаемых опытов проверяется create → advance → codec → branch.
Динамическое вращение сохраняет схему 10 и прежний запрет ветвления.
Кодеки чтения/записи остаются строгими и не принимают bool/NumPy в самом JSON.

Точные прежние исходники сохранены в
[numeric-before373.zip](../../scripts/validation/numeric-before373.zip).
Исторические scientific receipts относятся к своим исходникам; новый SHA
пакета меняет совместимость recipe и не квалифицирует новую точность JPL.
Побитовое совпадение измеряется отдельно от физической достоверности модели.

Общие изменяемые ссылки и численная устойчивость на крайних масштабах
оставлены отдельными задачами. Этот этап не исправляет обнуление силы при
промежуточном underflow и не заменяет алгоритмы нормирования/инерции.

## Результаты этапа

- Связанный набор с настоящим PyO3: **608 PASS, 0 skip, 140.68 с**.
  Включает независимые проверки движения/вращения, Python/Rust, Verlet/DOP853,
  обычные сохранения, контакты, ветки, continuous и запись траекторий.
- Быстрый Python CI: **562 PASS, 4 штатных deselect, 18.92 с**.
- Rust core: **19 PASS**, оба `cargo fmt --check` прошли; Rust не менялся.
- Десять документов трёх сценариев до/после при Python/Rust и Verlet/DOP853
  совпали побайтно. Дополнительно старые исходники проверяют 128 шагов на
  трёх эксцентриситетах, вращательное поле и интегрирование свободного тела.
- Все 14 файлов исходного архива сверены с Git `f3a68c9`. AST семнадцати
  вычислительных функций и четыре оператора обновления Verlet не изменены.

Промежуточный полный `--require-native` прогон: **2747 PASS, 22 FAIL,
15 ошибок подготовки, 841.36 с**. Отказы относятся к точным старым source SHA
в научных receipts/research-checkpoint. После него уточнены проверки
времени/timedelta и строгих настроек кодека; финальные наборы выше относятся
к этим уточнениям. Повторной полной приёмки после них нет: пользователь
выделил совместимость исследовательских привязок в отдельный этап.
Исследовательские guards, критерии и отчёты не ослаблены; FAIL не скрыты.
Новая точность относительно JPL и новая portable не квалифицировались.

Локальная оценка стоимости: 2 тела, Python Verlet, 20000 шагов,
пять чередующихся пар в прогретом процессе. Медиана CPU выросла
0.625 → 0.734375 с (+17.5%); wall 0.705689 → 0.803823 с.
Это цена дополнительных проверок в одном микросценарии, без запуска GUI;
результат не переносится на большие N или DOP853. Первый короткий CPU-замер
оказался слишком грубо квантован и сохранён отдельно, вывод по нему не делался.
