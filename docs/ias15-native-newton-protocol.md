# IAS15 с полной ньютоновской силой Rust: протокол 357

22 октября 2026, до реализации и результатов. Исследовательская замена
только источника ускорения; runtime, интегратор Rust и физическая модель
продукта не меняются. Основание: [356](ias15-session-validation.md),
[353](ias15-restart-validation.md) и
[проверенные первичные источники IAS15](integrator-candidate-review.md).

## Зафиксированные условия

Все девять прежних задач: шесть holdout по 82 эпохи, три original по 60,
исходные инерциальные binary64 массы/p/v, SI, t0=0, два периода, прежние
packet_dt и выходные эпохи. Оба epsilon 1e-9/1e-11, REBOUND 5.2.2,
PRS23, min_dt=0, softening=0, первый dt=packet_dt/200, exact_finish_time=1.
Один тёплый controller на траекторию. Нет COM-преобразования, relative_pair,
PN, фигур, вращения, интерполяции или перенастройки критериев.

Два варианта: встроенная C gravity=basic и полная сила реального
solar_native.point_acceleration через native_forces.prepare с light_speed=None,
relative_pair=None, gravity=none, force_is_velocity_dependent=0.
Python fallback запрещён. Проверять настройки до каждого пакета и после него;
включение basic вместе с callback отклонять, чтобы исключить удвоение силы.
Состояние публиковать только после callback.check, точного clock, finite и
physical JSON/SHA roundtrip. Ошибка, NaN, неверная форма или прерывание
callback защёлкиваются; исключение перекидывается до публикации результата.
Это стенд whole-trajectory, не новый пользовательский session/recovery API.

## Независимые проверки до полного прогона

Для каждой исходной конфигурации независимо вычислить ускорение из
градиента U=-G*m1*m2/r в Decimal100 с exact-from-float входами. Сравнивать
норму ошибки каждого тела с нормой эталонного ускорения: <5e-13.
Побитное равенство C/Rust сил не требуется. Дополнительно тестировать
реакцию сил, перестановку тел и вращение координат; наклонный аналитический
круг, отсутствие удвоения силы, исключение/NaN/shape/KeyboardInterrupt
из callback и явный отказ отсутствующего native-модуля.

## Полный опыт и неизменные критерии

Сначала offline replay353, затем C-контроль должен побитно воспроизвести
все 353 warm outputs, packet clocks/states, physical JSON/SHA и steps_done.
Rust-вариант проверяется по независимому actual-IC Decimal f/g-эталону338,
не по C-траектории: максимумы r<0.1м, v<1e-6м/с, относительные E/L/P<1e-10.
Эталонная неопределённость прежняя (<1e-6м/<1e-12м/с). Инварианты от исходных
IC, не переинициализировать. Сохранить все неуспехи и различия C/Rust.

На вариант: прогрев, три измеряемых повтора с точным совпадением массивов
и счётчиков. Таймер включает setup, callback/FFI, интегрирование, physical
JSON и извлечение снимков; исключает oracle/hash/файлы. C/Rust имеют разные
реализации силы и цену callback; отношение времени не есть ускорение метода.
Сохранить число пакетов, шагов, callback-вызовов, максимальные ошибки и
полные массивы. Исходники, native extension, библиотека и sdist SHA до/после;
новый output, source snapshot и partial receipt при отказе. После расчёта
offline replay из другого корня без C/native/.tools/сети и corruption guards.

PASS относится только к этим модельным задачам и coupling. Это не JPL,
не доказательство точности произвольной N-body системы, не устранение
coldFAIL353/355, не выбор лицензии/поставки IAS15 и не продуктовый backend.

## Техническое уточнение переносимости перед повторным прогоном

Первый опыт завершён со всеми36PASS, но проверка Git выявила LF в index и
CRLF в рабочей копии Cargo.toml/lock у solar_core/native. Их точные byteSHA
как публичные source bindings не переносились бы на Linux. Первый receipt,
массивы и точные исходники сохранены отдельно; критерии и уравнения прежние.
Для шести Cargo metadata хранить отдельные LF-нормализованные SHA (замена
только CRLF→LF), одновременно raw byteSHA до/после и проверку их неизменности
во время расчёта. Все алгоритмические .rs/.py, протокол и данные по-прежнему
проверяются по точным байтам. Структуру Cargo/код ядра/Git attributes не менять.
Повторить полный опыт в новом output и сверить все180массивов с первым;
отдельно проверить replay при смене EOL Cargo и отказ при изменении содержимого.
