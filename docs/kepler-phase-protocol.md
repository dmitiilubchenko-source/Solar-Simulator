## Независимый эталон

Ньютоновская относительная задача r'' = -mu r/|r|³, SI, произвольные
наклонные декартовы оси; t=0 соответствует записанному начальному снимку.
Абсолютная эпоха и эфемериды для этой модельной задачи не нужны.
Только невырожденные эллипсы, |n dt| ≤32 радиан; не general-purpose solver.

Из начальных r0,v0 вычисляются a=(2/|r0|-v0²/mu)^(-1),
n=sqrt(mu/a³), q=1-|r0|/a, s=(r0·v0)/sqrt(mu a).
Приращение эксцентрической аномалии u решает
u-q sin(u)+s(1-cos(u))=n dt. Его производная |r|/a положительна.
Бисекция использует заранее ограниченный интервал шириной |q|+2|s|+1.
Далее f=1-a(1-cos(u))/|r0|,
g=[a s(1-cos(u))+|r0| sin(u)]/sqrt(mu/a), r=f r0+g v0;
f'=-sqrt(mu a)sin(u)/(|r| |r0|), g'=1-a(1-cos(u))/|r|,
v=f' r0+g' v0. Формулы сверены с первичной реализацией
[Orekit Cartesian Kepler propagation](https://raw.githubusercontent.com/CS-SI/Orekit/develop/src/main/java/org/orekit/orbits/KeplerianMotionCartesianUtility.java)
(эллиптический раздел; это источник формул, не исполняемая зависимость).
[NASA/JPL PROP2B](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/spicelib/prop2b.html)
подтверждает постановку переноса исходного декартова состояния и ограничения
точности близ перицентра; его универсальный алгоритм здесь не реализуется.
Наш oracle использует Decimal, бисекцию и ряды sin/cos с защитными разрядами,
независимо от production DOP853, сил и номинальных элементов.

## Заранее заданные проверки

- Прежние e=0/.5/.95, исходная конструкция начальных данных, 2 номинальных
  периода и все прежние 60 эпох, включая окрестности перицентра.
- Главный эталон: точные Decimal-разности сохранённых float64-компонент,
  mu = exact(G_float)*(exact(m1_float)+exact(m2_float)).
  Отдельно показать чувствительность к округлённым relative-переменным
  solver и к сумме отдельно округлённых GM, используемых native-силами.
  Эти соглашения не подбирать по будущей траектории.
- Decimal70 против Decimal100: неопределённость <1e-6 м и <1e-12 м/с;
  дополнительно бюджет округления конечного эталона в float64. Точное t0,
  аналитические четверти круга mu=r=v=1, обратимость наклонного эллипса,
  его независимые E/L. Проверять до применения oracle к production.
- Старые и новые результаты хранить отдельно. Главные пределы прежние:
  относительные положение <0.1 м, скорость <1e-6 м/с, E/L/P drift <1e-10.
  Это критерий данной задачи/сетки, не гарантия для произвольной песочницы.
- Сначала строгий tightabs production без правок. Следующую чувствительность
  шага/метода объявить отдельно до расчёта. Не повышать пороги, не подгонять
  фазу/массу, не проецировать энергию для получения желаемой орбиты.
- Сохранять входные массивы, времена, результаты, стоимость/RHS и SHA
  исходников до/после каждого прогона. Полные runtime-проверки и новая
  portable-сборка нужны при внедрении runtime, не при добавлении oracle.
