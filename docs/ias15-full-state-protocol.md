## Будущий pilot363, до первого измерения

- Прежний `holdout_circular` из353: фактические IC/GM/origin и исходная
  аналитика actual-IC через тот же проверенный load_cases. Два Newton point
  mass, SI, без softening/PN/вращения/контактов/COM shift. Не заменять IC
  более удобным точным кругом. Продолжительность, epochs и packet_dt берутся
  из закреплённого случая, без изменения сетки ради результата.
- Оба прежних epsilon1e-9/1e-11, PRS23, min_dt0, первоначальный
  dt=packet_dt/200, exact_finish_time1. Рецепты: один warm controller;
  повторное создание из полного binary после каждого committed packet;
  прежний physical JSON cold reset как отдельный контроль. Гравитация basic;
  native callback вводится только следующим отдельным шагом после basic.
- Для каждого пакета сравнивать все x/v, время, GM/G, flags/model и все
  17 выводимых полей IAS15, длину буферов и dt/dt_last_done. Состояние после
  загрузки и дальнейшие outputs должны быть битовыми warm-control. Времена
  CPU/walltime и адреса указателей не критерий численной идентичности.
  Не вызывать synchronize/getSimulation(close/exact) и не сбрасывать поля.
- В старом metrics остаются прежние ограничения независимой actual-IC
  аналитики: положения/скорости и E/L/P берутся из353 без ослабления.
  Побитность warm/full сама по себе не отменяет абсолютный численный FAIL.
  Сохранять физический JSON отдельно от research binary, не менять storage.
- Запись должна создавать новый файл: запрещены перезапись существующего
  результата, append delta-chain и delete_file=True. Допустим исследуемый
  memory stream с той же C-функцией; не использовать pickle.loads.
  Размер, SHA, origin, порядок/masses, эпоха, epsilon/model, версия/ABI и
  SHA библиотеки закрепляются до передачи bytes C-конструктору.
- Работать только с доверенным самостоятельно созданным snapshot на той же
  pinned библиотеке/ABI. Предварительная проверка структуры/размеров и SHA
  обязательна: повреждение не передавать C-reader ради проверки его защиты.
  Outer SHA не заменяет проверку embedded field names/lengths/model.
- Все C warning bits и Python RuntimeWarning должны быть проверены до
  интегрирования. Для basic без callback допустим только нулевой набор.
  Для будущего native разрешён только заранее ожидаемый POINTERS=4 с
  явным повторным связыванием проверенного callback и проверкой силы до
  integrate. Скрывать process_warnings=False или глобально игнорировать
  RuntimeWarning запрещено. Неизвестный bit отклонять, даже если Python
  BINARY_WARNINGS его не содержит. Callback counters/exception latch и
  committed state должны иметь собственный проверяемый sidecar.
  До экспорта проверить отсутствие всех неподдерживаемых callbacks, включая
  pre_timestep_modifications: общий POINTERS flag не покрывает каждый hook.
- Negative проверки: version/library/ABI mismatch, другой origin/mass/time,
  недостающий/укороченный/дублированный buffer, повреждение SHA/структуры,
  неожиданный callback/warning. Отклонение до C-load/integrate; текущий
  committed physical snapshot остаётся доступным при любом отказе.
- Измерять integration, сериализацию, чтение и byte size раздельно.
  Не выдавать новый Python/IO wrapper за ускорение численного метода.

Только после pilot PASS — отдельный прогон всех девяти прежних случаев,
двух epsilon и всех committed boundaries с прежней независимой аналитикой.
Отдельно исследовать native coupling и новый процесс. Перенос на другой PC,
Solar checkpoint, внедрение/лицензия и Rust-реализация этим не принимаются.
Обнаруженный FAIL сохранять целиком; не выбирать удачную точку восстановления.
