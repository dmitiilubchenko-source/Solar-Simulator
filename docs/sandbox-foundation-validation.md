# Проверка основы песочницы

14 октября 2026, изменение 120. [Протокол](sandbox-validation-protocol.md)
зафиксирован до расчётов. Ни силы, ни интеграторы, ни закреплённые данные
в этом блоке не изменялись. Добавлены границы состояния и ветки опытов.

## Что исправлено и почему

До исправления 8 из 9 новых регрессионных проверок не прошли:
ручное изменение position/velocity/spin при t=0 принималось и расчётом,
и сохранением; изменённый JSON также загружался. Причина — frozen Body
содержит изменяемый Vector3, а загрузчик проверял состав, но не равенство
исходных векторов. Новая проверка применяется к t=0 без контактных событий;
допустимые контактные скачки в нулевой момент не запрещаются.

В свежем процессе импорт Experiment падал при отсутствии каталога астероидов:
Experiment импортировал кольцо, оно — perturbers с чтением каталогов на уровне
модуля. Кольцо теперь импортируется при выборе его сценария. Проверена также
загрузка старого ring/Q2 checkpoint в свежем процессе: регистрация наследуемых
источников выполняется по требуемому происхождению. Выбранные источники всё
ещё проверяются по SHA; отсутствие данных не маскируется другим сценарием.

API веток и GUI проверяют полную сохранность родителя, отдельные векторы,
новый старт/энергетический баланс, сохранение и продолжение, добавление второй
звезды, удаление Солнца и свободное движение оставшегося тела. В реальных
Tk-виджетах проверены отмена, отказ атомарной записи, применение массы x2,
загрузка дочернего опыта и reset. При отказе старый файл и опыт сохраняются.

## Первый годовой профиль

Пользователь согласовал 10 тел и год. Здесь проверен ограниченный Newton-профиль
с относительной Earth–Moon; он не заменяет лучшие ранее созданные EIH/Q2-профили.
[Полный результат по каждому телу](sandbox-planets-validation.json), повторение:

```powershell
.venv/Scripts/python.exe -X utf8 -B scripts/assess_sandbox_planets.py
```

Закреплённые epoch JD2461321.5 TDB, Ecliptic J2000, SSB, GM и родительские
наборы согласованы; GM Earth+Moon совпадает с системным EMB, повторной массы нет.
45 эпох, остальные планеты сравниваются с JPL в 13 годовых эпохах.
RK45 использует другую формулу организации пар и безразмерные переменные;
чувствительность двух строгих эталонов 1.716 м, время 2.020 с.

Максимум численной разности: 1.997 м Python / 1.991 м Rust (Moon);
максимум скорости 5.17e-6 м/с. Пороги 100 м / 1e-3 м/с прошли для всех тел.
Изменение rtol 1e-13→3e-14 меняет положения до 0.0215 / 0.0196 м.
Годовой свободный расчёт: 0.704 / 0.467 с, более строгий 0.673 / 0.442 с.
Это стоимость только расчёта на текущем PC, без GUI и загрузки, одиночные замеры.
С чувствительностью эталона 1.72 м результат нельзя объявлять доказанной
абсолютной физической точностью в 2 м или сантиметрах.

## Отказы во время разработки и границы

Помимо восьми воспроизведённых ошибок, новые стенды сначала выявили ошибки
своей обвязки: NumPy scalar вместо встроенного float не прошёл строгую схему;
импорт helper из tests не был доступен в свежем subprocess; выбор ttk.Entry
захватил ttk.Combobox и изменил имя вместо массы. Исправлены преобразование
на границе SI, локальный импорт helper и выбор точного класса виджета.
Пороги аналитики не менялись. Итоги полного прогона записаны в журнале 120.

Первый полный прогон: 4 отказа / 1291 успешно, 186.68 с. Отказы относятся
к SHA perturbers.py, закреплённому в старых научных отчётах: временная правка
ленивой регистрации изменила исходник. Каталожный модуль восстановлен
побитно (SHA e0760dd806798a8c0bbf4cba03bbae3c12181fa649abd5432ba980d190fbe7d5),
регистрация перенесена в загрузку нужного checkpoint; старые JSON результатов,
пороги и SHA не переписывались. 88 целевых проверок, включая четыре отказа
и новый свежий ring/Q2 load, прошли за 13.99 с. Аналитический отчёт повторён
после изменения storage, численные ошибки прежние. Повторный полный прогон:
1295 Python-тестов прошли за 171.21 с, 17 Rust-тестов прошли,
cargo fmt для solar_core/solar_native прошёл. Итоговые file/line ссылки
1365 и относительные локальные ссылки 643 прошли. Проверены SHA исходников
обоих новых JSON-отчётов; проверки в них успешны.

Обязательные проверки в чистой среде без личного .tools пока не доказаны:
прежний исследовательский fixture lunar_initial_boundary требует архив.
Полный GUI добавления/шаблонов, возврат к родителю кнопкой, управление временем
и сертификация физической ошибки продукта остаются следующими этапами.
Portable в данном блоке не пересобиралась; проверка относится к исходникам.
