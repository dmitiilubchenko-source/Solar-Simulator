# Границы достоверности изменённых систем: протокол 190

15 октября 2026, до новых траекторий. Runtime, исходные данные, старые
научные отчёты и portable сохраняются. Никаких новых сил или интеграторов.

Проверить существующую границу: branch_experiment сохраняет родителя,
создаёт дочерний t=0 с собственной энергетической базой и origin=None.
Происхождение начальных данных не является сертификатом точности.
Правки массы, положения, скорости, добавление и удаление тела проверить
на исходном строгом EIH+fixedJ2 профиле и после 86400 с; сохранение/загрузка,
сброс, обычный checkpoint, bundle, CLI и CSV не должны возвращать дочернему
опыту JPL origin или изменять родителя. Не вводить новую схему хранения.

Отрицательные проверки: совпадение положений, внутренняя область J2,
сверхпороговая скорость/масса для существующего weak-field guard,
удаление источника J2 или тела относительной пары. Отказ должен сохранить
родителя. Эти guards задают область приложения, не количественную точность
1PN или J2. Prescribed orientation/rigid spin остаются запрещены для веток.

Независимая динамическая проверка: пять ньютоновских связанных 3D-пар без
J2/контактов/вращения, Python и Rust, прежние настройки sandbox-limits:
DOP853, per-body, rtol=1e-13, xatol=1e-3 м, vatol=1e-9 м/с, dt=3600 с,
max_steps=20. Четыре прежних случая mass-double, slow-velocity,
eccentric-095, add-companion сохраняют свои 33 эпохи на одном периоде.
Новый position-edit: исходная круговая пара того же сценария, смещение
Companion на (0.03R, -0.02R, 0.04R), R=1.5e11 м, при прежней скорости.
Сетка — 33 равномерные эпохи на одном периоде, оценённом из новых IC.
Это также проверяет старт вне апсиды; исход и орбита не задаются извне.

Главный эталон — уже проверенный Decimal f/g в scripts/kepler_reference.py,
точные разности фактически сохранённых float64-компонент при precision=110,
mu=exact(G_float)*(exact(m1_float)+exact(m2_float)). Номинальные R/U/W,
апоцентр, фаза и элементы исходного fixture не заменяют эти IC.
Decimal70/100 должны согласоваться <1e-6 м / 1e-12 м/с; exact t0 обязателен.
Формулы [Orekit](https://raw.githubusercontent.com/CS-SI/Orekit/develop/src/main/java/org/orekit/orbits/KeplerianMotionCartesianUtility.java)
проверены в первичной реализации; [JPL PROP2B](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/spicelib/prop2b.html)
описывает постановку переноса декартова старта. Оба источника прочитаны;
они не являются исполняемыми зависимостями нашего эталона.

SI, произвольные наклонные инерциальные оси, t=0 — старт нового опыта;
эфемеридной эпохи нет. Пороги прежних sandbox-limits: относительные
положение <10 м / скорость <1e-5 м/с, движение COM <0.01 м,
нормированные ньютоновские E/P/J <1e-10. Серединный checkpoint должен
продолжаться побитово, все выходные эпохи точные, родитель неизменен.
Численная ошибка считается непосредственно в Decimal, без предварительного
округления эталона в float64; отдельный бюджет такого округления записать.

Для четырёх старых случаев отдельно измерить разницу прежнего номинального
аналитического эталона и actual-IC эталона. Не вычитать её из ошибки и не
переписывать прежние результаты. Старый номинальный helper не использовать
для нового position-edit: он специально привязан к своей геометрии.

Записать IC/массы/времена/траектории, ошибки, индивидуальные интервалы,
однократную стоимость reference и production, source/input/native binary
SHA до/после. Прежние cached результаты переиспользуются только по SHA.
Один замер не доказывает преимущество Python/Rust по производительности.
Никакой JPL-точности, гарантии между эпохами, всех редактируемых систем,
сближений, гипербол, EIH+J2 или большего срока этот набор не сертифицирует.
Прежний провал DOP853 при e=.95 на более строгом двухпериодном критерии
0.1 м / 1e-6 м/с сохраняется; иной порог и иной сценарий не исправляют его.
