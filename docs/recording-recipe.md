# Рецепт записи и проверка повторного расчёта

Изменение319, 19 октября2026. Каждая новая запись траектории из GUI/CLI
автоматически получает `recipe.json`. Прежние manifest v1 и полные кадры
сохраняют формат. Рецепт связывает записанный опыт с файлами кода,
окружением и фактическими границами пакетов. Он не подтверждает точность
физической модели относительно природы или эфемерид.

## Как пользоваться

1. [Записать траекторию](trajectory-recording.md) прежней командой
   `record-trajectory` или кнопкой лаборатории. Выбор интегратора/допусков
   и пакета остаётся численной настройкой, скорость просмотра отдельная.
2. В окне просмотра нажать «Рецепт…». Выполняется проверка рецепта,
   соответствия записи и нынешних файлов/окружения; решатель не вызывается.
   Чтение и хеширование зависимостей может занять несколько секунд.
3. Для повторного расчёта запустить CLI, указав новый каталог результата:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m solar_simulator check-recipe recorded-trajectory
.\.venv\Scripts\python.exe -X utf8 -B -m solar_simulator replay-trajectory recorded-trajectory repeated-trajectory
```

`check-recipe`: код0 означает совместимость по выбранным признакам,
код1 — несовпадение/неподтверждённую опись зависимостей; неверный/отсутствующий
рецепт — ошибка2. Вывод перечисляет категории несовпадения и неподтверждённые
зависимости. «Стабильность» обозначает равенство начального и конечного
снимков файлов, а не полную проверку исполнения или научную квалификацию.

`replay-trajectory` проверяет исходную запись/рецепт и окружение до создания
результата. Затем выполняет расчёт тем же backend, с теми же настройками,
исходной конечной целью и числом опубликованных пакетов. В новом каталоге
появляются обычная траектория с собственным рецептом и `replay-report.json`.
Код0 — все полные кадры совпали в текущей среде; код1 — несовпадение,
данные повторного расчёта сохранены для диагностики; ошибка2 — некорректный
вход/окружение/запись. Технический отказ расчёта по-прежнему сохраняет recovery.

Исходный каталог не изменяется. Существующий каталог результата не используется;
выход внутри исходной записи запрещён. Повтор не устанавливает пакеты,
не меняет окружение и не выполняет команды из JSON.

При несовпадении нужно восстановить соответствующую копию исходников
и дистрибутивы зависимостей. [Проверенный способ установки](reproducibility.md)
описывает текущий desktop-профиль; его версии должны соответствовать рецепту
конкретной записи. Новый код/окружение можно использовать для отдельного
эксперимента с новым рецептом и собственными проверками.

Записи до319 без рецепта продолжают открываться и проигрываться.
Проверка происхождения и повтор через этот режим для них отклоняются:
задним числом нынешние файлы нельзя объявить исходниками старого расчёта.
Полный исходный checkpoint можно использовать для нового расчёта и новой
записи с честно зафиксированным нынешним окружением.

Это функции исходного проекта. Portable315 не пересобрана и их не содержит.

## Что зафиксировано

`recipe.json` — оболочка payload/SHA256. Payload версии1 содержит:

- два снимка окружения: до записи и после последнего опубликованного пакета;
- версию приложения и SHA Python-файлов/JSON/TXT текущего пакета, с относительными
  именами; это учитывает незакоммиченный код, одного git HEAD недостаточно;
- версии замыкания обязательных runtime-зависимостей NumPy/SciPy/Matplotlib,
  отобранные по активным маркерам requirements; SHA их py/pyd/dll/so из
  установленной описи файлов, включая подходящие библиотеки соседних `.libs`;
- признак проверяемости описи: missing metadata/files и editable-зависимости
  не получают разрешения на строгий повтор, даже при совпадении версии;
- для backend Rust — SHA настоящего установленного compiled solar_native
  и его Python-обёртки/версию; Python-замена extension отклоняется;
- Python version/implementation/ABI/free-threaded build, разрядность,
  endian/optimize, SHA базового executable и доступной общей библиотеки Python;
- ОС/release/архитектуру и выбранные численные переменные окружения
  OMP/OPENBLAS/MKL/VECLIB/NUMEXPR threads, PYTHONHASHSEED;
- полный manifest записи, его SHA и пары фактических времён соседних кадров.

Полный первый кадр manifest содержит исходный checkpoint: текущие/начальные
тела в SI, settings, время, Origin, события, spin/rotation/work и parent для
ветки. Его SHA входит в привязанный список. Поэтому рецепт переносится
вместе с каталогом записи, а не отдельно от файлов кадров. Все последующие
снимки также связаны своими SHA. Источники данных в Origin сохраняются
прежним форматом, а файлы встроенных данных получают SHA пакета.

В рецепт не включаются абсолютные пути установки/проекта/выхода, hostname,
личные документы, все переменные окружения или содержимое direct_url.json.
Из последнего читается только признак editable; частный путь не экспортируется.
Численные env-настройки допускают только числовой текст (или random для
PYTHONHASHSEED), прочие значения отклоняются явно. Файлы scientific cache
в .tools и исходники исследовательских стендов не выдаются за runtime.

## Пакеты, прерывание и отрицательный результат

Повтор использует `advance_towards(state, original_target, original_batch)`.
Он не заменяет исходную конечную цель последней опубликованной эпохой:
это могло бы изменить разбиение и округления DOP853. Число вызовов ограничено
длиной исходного опубликованного префикса. Короткий последний интервал
и конечные before/after контакта в одном времени сохраняются прежним способом.

Остановленная/failed/interrupted запись может иметь пригодный рецепт префикса.
Его совпадение не означает достижения первоначальной цели. Отчёт явно
разделяет source/replay status, requested target и last committed time.
Программная ошибка из исходного запуска не обязана воспроизводиться: сравниваются
его опубликованные состояния, не будущий незаписанный участок и не orphan-файлы.

Сравнение охватывает все индексы и количество кадров, а не только zip-префикс,
координаты или конечную точку. По SHA полного checkpoint обнаруживаются отличия
скоростей, событий, родителя, вращения, потерь/работы и состава системы.
Повторное окружение дополнительно должно совпасть с исходным снимком рецепта.

Ошибка финальной записи рецепта не уничтожает готовые кадры. Команда сообщает
отказ и сохраняет последнее рассчитанное состояние в recovery. Неоконченный
рецепт не проходит аудит, но опубликованный префикс остаётся доступным для
просмотра. Обнаруженный дрейф файлов остаётся отрицательным результатом:
cleanup использует уже сделанный конечный снимок, а не стирает свидетельство
новой попыткой чтения после возврата файлов к прежнему виду.

## Область доказательства и ограничения

SHA обнаруживает изменение относительно рецепта; это не подпись автора.
Описаны выбранные файлы установленного окружения, а не полная герметичная
копия ОС. Опись из package RECORD не гарантирует обнаружение всех возможных
внешних библиотек/ресурсов; поддержаны перечисленные суффиксы, текущий
desktop-аудит относится к Windowsx64/CPython3.14t. Editable проект Solar
поддержан прямым хешированием пакета; editable сторонние зависимости для
строгого повтора не подтверждаются. Missing inventory отклоняется явно.

Это снимки файлов до/после, не аттестация объектов уже загруженного процесса.
Не поддерживаются hot reload, замена кода в памяти, отслеживание каждого
мгновения запуска или изменение файлов с последующим скрытым восстановлением
между снимками. Процесс следует запускать после установки нужных файлов;
для проверки используется отдельный процесс. Хеш native фиксирует фактический
binary, не доказывает его происхождение от нынешнего Rust-дерева/toolchain.
Код/дистрибутивы не архивируются рецептом и автоматически не устанавливаются.

Различие даже неиспользованного файла пакета может консервативно запретить
повтор. Совпадение признаков окружения само по себе не обещает одинаковые
инструкции CPU/BLAS/thread schedule на другом компьютере; окончательный
проверяемый факт — совпадение всех пересчитанных кадров этого опыта.
Воспроизведение на любых платформах и истинная физическая точность не заявлены.

Хеширование выполняется в начале и конце записи, не на каждом пакете.
Цена заметна на коротком опыте; запись рецепта увеличивает объём каталога.
Это сознательная цена проверяемости, не оптимизация решателя. Viewer хранит
кадры целиком в памяти, как раньше; recipe/manifest используют общий лимит
атомарного writer10МБ. Очень длинная запись может упереться в этот лимит
и останется с явно неподтверждённым рецептом и сохранённым префиксом/recovery.
