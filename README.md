## Направление следующей версии

Solar развивается в физическую песочницу: Солнечная система — исходный
сценарий, а ядро рассчитывает также пользовательские гравитационные системы.
Главный приоритет — научно обоснованное движение планет с воспроизводимыми
проверками и измеренными ошибками. Графика 3D пока отложена.

В исходной версии доступны редактор массы/положения/скорости, добавление
звезды или планеты с явными начальными условиями, сохранённая ветка нового
опыта после редактирования на паузе и [расчёт вперёд до времени](docs/time-control-validation.md).
Текущие возможности и ограничения описаны в руководстве.
Первая готовая песочница от14октября: [проверенная portable](docs/sandbox-portable-validation.md)
и [сценарий демонстрации](docs/sandbox-demo.md).
[Новый блок125–134 и свежая сборка](docs/sandbox-reproducibility-validation.md)
добавляет воспроизводимую установку, работу с родителем, удаление и CSV.
[Измеренная оптимизация отрисовки](docs/runtime-performance-validation.md)
уменьшает стоимостькадра, сохраняя все снимки и прежнюю физику.
[Плотная численная проверка и отдельный строгий профиль](docs/qualification-extension-validation.md)
сохраняют непройденный критерий старого профиля и показатели изменённых систем.
[Новое сравнение с JPL на125эпохах всех10тел](docs/dense-jpl-validation.md)
прошло прежние физические цели; измеренный максимумMoonrelative719м.
[Автономная проверка и новый годовой расчёт](docs/verification-bundle-validation.md)
поставляются с portable: сохранённые траектории и реальное интегрирование проверяются отдельно.
Развитие вращения следует после движения планет; расширение столкновений,
слияний и приливы в первую песочницу не входят. Прежние режимы сохраняются.

Сейчас адаптивный интегратор и часть моделей работают на Python/SciPy,
а Rust вычисляет силы и отдельные полные циклы расчёта. Долгосрочная цель —
самостоятельное физическое ядро Rust, переносимое по проверенным компонентам.
Каждый перенос проверяется независимо; Python служит проверочной реализацией.

Рабочий цикл: задача и критерий правильности → реализация → независимая
проверка → оценка результата → необходимое улучшение → повторная проверка.
Оптимизация оценивается по измерениям стоимости вместе с ошибкой расчёта.

[Требования и порядок развития песочницы](docs/sandbox-roadmap.md)
разделяют согласованную область, текущие ограничения и открытые решения.

В исходной версии добавлена [основа веток пользовательских опытов](docs/sandbox-experiments.md):
редактор сохраняет исходный и новый опыт одним файлом; headless API позволяет
заменять, добавлять и удалять тела. В исходном GUI также доступны добавление
точечного тела с явными SI векторами и готовый10-тельный профиль EIH+FixedSun/EarthJ2.
Расчёт до целевого времени доступен; возврат назад пока через JSON/сброс
и пересчёт. Стартовый проверяемый набор — 10 тел, один год.
[Измерения](docs/sandbox-foundation-validation.md) отделяют численные ошибки
от остатков относительно JPL; это не заявление полной физической точности.
[Сравнение моделей и новые команды GUI](docs/sandbox-models-validation.md)
сохраняет непройденные цели Newton/EIH и измерения успешного годового профиля.

## Установка для разработки

[Проверенный профиль установки и воспроизводимость](docs/reproducibility.md)
описывает версии зависимостей, явные GNU-инструменты и публичные входы тестов.

Python 3.11 или новее с Tk:

Для повторения опубликованных измерений используйте проверенный Windows x64 /
CPython 3.14t и constraints ниже. Это не проверка всех Python ≥3.11 и платформ;
для другой среды нужны отдельные проверки. Переменная команда `python` должна
выбирать нужный интерпретатор до создания `.venv`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,native]" -c requirements/validated-windows-cp314t.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -B scripts/build_native.py
& "$env:USERPROFILE\.cargo\bin\cargo.exe" build --release --manifest-path rust/solar_core/Cargo.toml
.\.venv\Scripts\python.exe -B scripts/check_project.py --require-native
```

Python-ядро работает без Rust. Для native-сборки нужен Cargo;
подготовка Windows GNU-инструментов описана в `docs/rust.md`.
Обычный checker без `--require-native` сохраняет прежнюю политику пропусков.
[Выбор Standard/Strict и область проверок](docs/profile-selection.md).
На текущем компьютере используется CPython 3.14t; native wheel
привязан к соответствующему ABI. Переносимая сборка включает этот Python.

## Работа через CLI

```powershell
.\.venv\Scripts\python.exe -B -m solar_simulator new sun-earth initial.json --backend rust --integrator verlet
.\.venv\Scripts\python.exe -B -m solar_simulator run initial.json final.json --steps 4000
.\.venv\Scripts\python.exe -B -m solar_simulator inspect final.json
.\.venv\Scripts\python.exe -B -m solar_simulator converge initial.json --steps 4000
```

Сценарии: `sun-earth`, `earth-moon`, `binary-star`, `sun-earth-moon`,
`spheres`, `solar-system`, `solar-system-moon`, `solar-system-pluto`, `solar-system-asteroids`, `solar-system-asteroids-full`, `solar-system-asteroids-catalog`, `solar-system-kuiper`, `solar-system-kuiper-ring`. Для Солнце–Земля есть `--eccentricity`; физический dt
можно задать через `--dt`. Контактные режимы: `stop`, `bounce`, `merge`.
У астрономических сценариев исходные радиусы нулевые, у `spheres` — 1 м.

## Модель и ограничения

В основной N-body-модели величины в SI. Гравитация точечных масс, Velocity Verlet с фиксированным
шагом или DOP853 с адаптивным шагом и допусками (Python/SciPy, без контактов), попарный алгоритм O(N²). Радиусы используются для контактов;
экранные маркеры имеют условный размер. Отскок гладких сфер сохраняет
импульс и учитывает потери. При слиянии сохраняются масса, импульс,
объём и полный угловой момент, включая пассивный внутренний `spin`.
Скачок разрешённой энергии при смене модели записывается отдельно.

Начальные состояния solar-system и solar-system-moon взяты из JPL; модели точечных тел
не воспроизводит всю физику DE441. Доступен отдельный режим EIH 1PN для слабого поля
и медленных точечных тел без вращения. Нет высших порядков ОТО, приливов, трения, гидродинамики,
разрушения, вращения нескольких несферических тел и контактных сил для устойчивых или
одновременных контактов. Такие контакты явно отвергаются. Уменьшай dt
при тесных сближениях и проверяй сходимость; графики по снимкам могут
пропускать промежуточные пики. Подробные границы — в руководстве.

[16 крупных астероидов SB441-N16](docs/asteroids-full.md): 27 взаимодействующих тел, прежний контрольный набор.

[Аудит недостающих масс](docs/perturber-audit.md): проверенный каталог DE441,
массовый охват астероидов и источники следующего расширения.

[Данные всех 343 астероидов](docs/asteroids-343.md): независимая проверка чтения,
измерение пропущенных сил и стоимости полного расчёта.

[Рабочие силы Newton/EIH на Rust](docs/native-eih.md): годовая независимая проверка 27 тел, контроль большого набора и измерение скорости.

[Все 343 астероида DE441 в рабочем расчёте](docs/asteroids-catalog.md):
`solar-system-asteroids-catalog`, 354 взаимодействующих тела и годовая проверка.

[Орбита по реальным наблюдениям MPC](docs/orbit-observations.md): отдельный
офлайн-подбор шести параметров астероида и проверка прогноза на поздних измерениях.
Команда `fit-orbit`; направления наблюдателя и планетный фон задаются DE441.

[Длинный прогноз и коррелированные ошибки ночи](docs/orbit-cohort.md): два
астероида, две станции, целые отложенные сезоны и явная проверка неопределённости.

[30 отдельных объектов пояса Койпера](docs/kuiper.md): общий шаблон,
384 взаимодействующих тела, проверка чтения CSPICE и отдельный годовой контроль.

[Экспериментальная автономная аппроксимация кольца Койпера](docs/kuiper-ring.md):
сценарий по умолчанию содержит 420 тел и оставлен для сравнения; он не прошёл
геометрический критерий. Отдельное уточнение до 528 тел прошло заданные
численные и геометрические проверки главных систем, но остатки отдельных KBO
относительно SB441 выросли. Кольцо остаётся экспериментальным; эти проверки
не доказывают истинную физическую точность.

[Консервативное вращение](docs/conservative-rotation.md) и
[начальное вращение Луны](docs/lunar-spin-initial.md) получили отдельный
[рабочий ньютоновский N-body режим](docs/nbody-rotation.md): одна динамическая
твёрдая фигура, обратные силы/моменты, общий баланс E/L, сохранение и продолжение.
CLI: `--rotation lunar-solid`; независимые проверки выполнены за 32 суток
для пары, Sun/Earth/Moon и исходных 10 тел, затем за
[год для исходных 10 тел](docs/rotation-year.md). Численные критерии прошли,
но остаток ориентации DE441 вырос до 121.84″ за год; это не физическая точность.
EIH и приливы с вращением
пока не реализованы; это ограниченная жёсткая модель Луны.

[Расширение380](docs/two-q2-380.md) поддерживает две динамические фигуры
в headless Newton-режиме: оба вращения, реакции, общий E/P/L и save/resume.
Это усечение M-Q без Q2-Q2 и высших моментов, проверенное на синтетических
2/3тельных системах. Оно не наследует годовую аттестацию старых SHA;
новые реальные параметры Земли/Луны не добавлены.

В исходниках dev [учебный пример двух фигур](docs/two-q2-laboratory.md)
доступен кнопкой в Laboratory: проекции главных осей, read-only q/S/ω и
существующий отчёт численной надёжности. Старый portable автоматически
не обновляется; это ещё не квалификация0.3.3.

[Контракт PN/спина и отдельный канонический стенд](docs/pn-spin-contract.md)
проверяют двухтельный гамильтониан и обратную SO-реакцию. Этот стенд
не подключён к рабочему вращению Луны; преобразование начальных переменных
и PN-фигура требуют следующих независимых проверок.

[Каноническая N-body модель 1PN + ведущий SO](docs/nbody-pn-spin.md)
проверена отдельно на трёх телах с несколькими спинами и тройными
потенциалами. В отчёте сохранён отказ короткого отрицательного контроля
и успешное отдельное продолжение; в этом стенде инерция/q/Q2 отсутствуют.

[Исследовательская согласованная PN/rigid-Q2 модель](docs/rigid-pn.md)
добавляет инерцию и ориентацию одной фигуры с полным балансом выбранного H.
Проверены независимый эталон, реакции, model restart и обращение времени.
Для рабочей Луны ещё нужны проверенные преобразования начальных данных;
полная PN-физика фигуры и приливы этой моделью не заявляются.

[Проверка начальных канонических переменных](docs/canonical-initial.md)
восстанавливает импульс и spin из скорости центров и скорости ориентации
выбранной модели. Лунная оценка условная: полного физического переноса
DE441 в PN/rigid-базис и рабочей PN-Луны пока нет.

[Отдельный канонический checkpoint](docs/canonical-checkpoint.md) хранит
x/p/S/q и их происхождение без подмены прежних velocity-схем. Файловый
restart и bitwise round-trip проверены; это исследовательский формат.

[Условная PN/rigid задача Солнце–Земля–Луна](docs/lunar-canonical.md)
прошла отдельный 32-суточный аудит с двумя независимыми эталонами.
Это исследовательская boundary projection; физическая точность и полный
перенос DE441 не заявляются, рабочий PN-режим ещё не подключён.

[Канонический conditional аудит исходных10тел](docs/canonical-solar.md)
также прошёл32суток с двумя новыми независимыми эталонами, tighter и
файловым restart. Численная чувствительность и физические ограничения
показаны отдельно; рабочая PN-Луна пока не подключена.

[Относительная каноническая пара Земли и Луны](docs/relative-canonical.md)
проверена отдельно: стабильная геометрия, согласованные импульсы и
32-суточный независимый аудит. Численное согласие отделено от физической
точности; перенос в рабочее приложение и формат сохранений ещё впереди.

[Строгий формат относительного канонического состояния](docs/relative-canonical-checkpoint.md)
сохраняет пару, порядок тел, происхождение и сырые X/r/P/pr/S/q.
32-суточное продолжение после JSON-загрузки в новом процессе проверено;
формат исследовательский, рабочее PN-вращение пока не включено.

[Масштабы времени и кинематика вращающегося базиса](docs/rotation-time.md)
проверены независимыми модельными задачами. Происхождение инерции и
полный физический перенос начальных данных Луны ещё требуют отдельного

## Ветки и следующий выпуск

Разработка ведётся в `dev`; в `main` далее переносятся принятые выпуски.
Первый публичный выпуск сохранён тегом `v0.2.0`. Текущая `main` содержит
более новый checkpoint, поэтому не является точной копией этого тега.
В `dev` подготовлена **0.3.0**; публикация выпуска и перенос в `main` требуют согласования.
[Правила веток, нумерации и готовности](docs/release-workflow.md) отделяют
проверенные исходники, поставку приложения и физическую квалификацию.
